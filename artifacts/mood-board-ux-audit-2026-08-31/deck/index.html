Act I · The diagnosis03

One sentence, and it has to hold the whole audit.

The room itself is above class average — clean canvas/persistence seam, genuinely good command engine, rich multi-select, faithful templates, solid exports — but a post-GA document-kind split silently stranded the healthy proposal-owned path, so all new client work lands on the project-owned path, where creation, group drag, and duplicate are broken and Share was never wired in.

This is the spine of everything that follows: a strong instrument, with the only door new clients can reach opening onto its broken half.

Act I · What's already good04

This is not a teardown. The room is above class average.

The canvas owns transient gesture/view state only and emits one semantic commit per gesture; it imports no persistence, fetching or auth — rare discipline for an in-house canvas.

Canvas interaction expert
Command engine

revertFailedStructuralTransition — a three-way inverse that rolls back only the failed write's fields and preserves later unrelated edits.

Smart guides + group resize

Alignment and equal-spacing guides at a screen-constant tolerance; group resize scales proportionally about the anchored corner — the hard case, done right.

Templates

Materialization reproduces sections, items, positions and rotation exactly, and correctly offers "promote to selection" on owner-linked pieces.

Share dialog

"The best-designed dialog in the set" — label, expiry, one-time-reveal link, select-on-focus, an explicit only-a-hash-is-stored note.

Export trio + ⌘K

PNG, composition PDF and spec-sheet PDF all succeed cleanly; ⌘K recents are instant and correctly scoped.

Discipline, elsewhere

44px touch targets nearly everywhere; allow-listed return paths; a legible "Working boards vs Signed direction" lifecycle split.

Act II · The fracture05

Every new client document is funneled onto the broken path.

Two board-ownership paths exist in this codebase. One is healthy. The other is where every new agreement now lands, because new agreements lost their Boards facet.

New agreements lost their Boards facet when the commercial-document split shipped — an unannounced side effect, not a decision. The only surviving Boards-capable, Share-capable drafting room is a handful of pre-existing legacy proposals nobody can create fresh.

Act II · Defect 0106

The top, default option in the New Board picker fails every time.

"Blank board" is the first card in the picker. On a project board it throws a raw RPC name straight into the user's toast.

console · repeated, identical both times

Error logged: AppError: Project board changes require apply_board_room_state

Toast — "Error — Project board changes require apply_board_room_state."

packages/supabase/src/hooks/use-boards.ts:594–596 · boards-builder.tsx:179–189 useUpsertBoard() throws by design when the owner is a project. BoardsBuilder.handleBlank() calls it unconditionally for both owner kinds.

The Patina starter templates work fine from the same dialog — they route through the owner-aware materialize_board_template RPC instead. That RPC is the fix template.

Act II · Defect 03–0408

Share was never wired in — and new work can't find the door that has it.

D3 · Share, absent

A hard owner.kind === 'proposal' gate — confirmed absent from the room toolbar, the "More" menu, Present mode, and the Boards list. No per-row menu, no messaging.

Backend mint/resolve/revoke for project-owned shares already Passed at GA (AC2.16). This is a one-line UI gate sitting on top of finished, tested work.

D4 · The front door, missing

commercialDocumentExperience() maps every new agreement to the facet-less ServiceAgreementDraftingRoom — zero import of BoardsBuilder.

An unannounced side effect of the later commercial-document-kind split, postdating GA. No PRD or ruling addresses it.

Both need a ruling on where boards belong going forward — see the ask, slide 17.

Act V · Three paths · A12

The Steady Hand

Make the canvas hand-feel genuinely Figma-class.

Core moves
  • Drag threshold + no re-stack — stop promoting an item to the front on every nudge.
  • Shift = constrain — revisits AC1.13; Figma, FigJam and Canva all read Shift this way.
  • Untangle Alt's triple booking — duplicate, snap-suppress, and resize-from-centre currently collide.
  • 24px hit-areas + directional cursors on resize/rotate handles.
  • Cascade placement on every add, not just multi-file uploads.
  • Visible zoom controls at all widths — the canvas already ships the cluster; the shell suppresses it.
What it does NOT do

Nothing for sharing, clients, or studio workflows.

EffortM
RiskLow

Mostly BoardRoomCanvas.tsx + shell. Visual-regression and e2e coverage already exist for this surface.

Act V · Three paths · B13

The Client Loop

Complete the moment the board was made for: designer finishes at 9pm, client reacts overnight, approved pins march into procurement.

Core moves
  • Share parity everywhere boards appear — D3 plus list-card discoverability.
  • A lightweight verdict-capable guest link — revisits Ruling #2's "guest never offers verdicts" boundary, kept token-scoped and revocable, tap reactions only.
  • Visible verdict → send-to-schedule flow — an explicit "approved pieces → purchase pipeline" moment.
  • Edit/present placeholder parity, closing the waived four-surface parity AC.
  • Prefetch assets before Present for client-wifi resilience.
  • A cross-project verdict rollup — "boards awaiting reaction / approved / stalled."
What it does NOT do

Canvas hand-feel, studio delegation.

EffortM–L
RiskMedium

Guest-verdict security must stay structural — this is a revenue-adjacent guest surface, and migrations touch Strata.

Act V · Three paths · C14

The Studio Engine

Make boards work for teams and volume.

Core moves
  • Real URL unfurl — the sourcing wedge, feeding the price-true procurement spine.
  • Bulk "promote all" on template materialization — a 3x manual tax today, per template reuse.
  • Internal direction layer, distinct from client verdicts — never scoped in the PRD.
  • Cross-project boards view — mount the orphaned recents strip, then a studio-wide status rollup.
  • Naming prompt at creation — kills "Board 2."
  • Archived-boards list and studio-template asset validation at save.
What it does NOT do

Hand-feel polish, guest client loop.

EffortL
RiskMedium

New surface area, but little touches the canvas itself. Prioritize if studio-seat growth is the quarter's goal.
