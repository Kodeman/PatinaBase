Twenty planks, and neither direction skips one

Each one repairs a claim the app already makes, data it already holds, or a screen it already ships. Direction A and Direction B are built on top of this list, not around it — whichever Kody rules for, the floor is the same floor.

Ordered by the severity of what each one fixes — S0 funnel breaks first — not by cost. Four of the twenty are drawn in full below the list.

  • SP-01

    Every piece detail loads, and the error has a door

    An ambiguous vendor join fails every browse tap; qualifying the embed loads the screen, and the failure state keeps the chevron the loaded one has.

    F04

    Size S. No backend — client-side only.

  • SP-02

    The browse grid is one card size, and the chips can be reached

    The app’s only shopping surface runs off-canvas on first load, and the filter row clips at XXL type with nowhere to scroll.

    F05

    Size M. No backend.

  • SP-03

    The share names Patina, and the link opens the app

    A shared piece hands the recipient the designer portal’s title on a link that cannot open the app, installed or not.

    F01

    Size M. No migration, no edge function — a client-facing piece route plus an entitlement, portal-side.

  • SP-04

    A proposal is called what it is, and the sheet restates it

    The list calls an unsigned proposal “SIGNED,” and the e-sign sheet asks for a name without saying what it is agreeing to.

    F02F03

    Size M. One confirmation email on the existing send-email chokepoint.

  • SP-05

    The client’s project screen stops talking to the designer

    The client’s own project screen prints “CLIENT VIEW / Milestone” and a portal instruction written for the designer.

    F20

    Size S. No backend.

  • SP-06

    Guest work belongs to the guest

    A guest’s room and saves inherit onto the next account signed in on the same phone, and every count on Today presents device data as account data.

    F23

    Size M. No backend for the prompt — rooms and saved_items already accept the mirror.

  • SP-07

    The matched designer becomes visible (one filter)

    One query filter hides every lead created from the designer portal, so a matched client’s home reads byte-identical to a guest’s.

    F10

    Size M — the filter is one line; the sheet branch and the Studio row are the rest. No backend.

  • SP-08

    The bell shows what is already waiting; the permission is earned

    The bell reads “Nothing yet” beside a Studio listing an overdue decision, a due invoice and a proposal to review.

    F08

    Size M. apns-send and device_push_tokens already ship; add notification_log writes on two existing paths.

  • SP-09

    The last tap of a design request has a way back

    Sending a request throws a guest the full auth gate with no Cancel and no way to look around first.

    F27

    Size S. No backend.

  • SP-10

    The piece says what it is: size, lead time, maker

    A $4,000 chair carries no dimension, no lead time, and often the retailer’s name where the maker’s belongs.

    F17

    Size L. One migration on a frozen RPC contract, plus a catalog pass to fill vendor fields.

  • SP-11

    A piece can be put in a room, and room browse is the room’s

    The room’s own button opens the generic grid with no room filter, and nothing in the app can put a piece into a room.

    F15

    Size M. No backend — saved_items.room_id already exists.

  • SP-12

    Saved has a door, and opens where the pieces are

    The Companion’s only route to Saved hides until something is already saved, and Saved opens on a Boards tab that can never fill.

    F14

    Size M. No backend.

  • SP-13

    A client can start the conversation

    Messaging ships, but a client cannot start a thread — the Studio’s Conversation block is the one drawn without a chevron. (F21 survives only in this narrowed form.)

    F21

    Size M. No backend — both start-thread RPCs are already granted to authenticated.

  • SP-14

    Save once, and it is still saved tomorrow

    The real save route runs local-only, never seeds its own saved state, and a second tap can write a second row.

    F122

    Size M. No backend — saved_items already accepts a null room.

  • SP-15

    Money screens carry the date and the failure

    The due date on every list vanishes on its own detail screen, and a failed $4,250 hand-off leaves a live button under one crowded red line.

    F102

    Size M. No backend.

  • SP-16

    One count, and a budget that is a budget

    One screen prints three disagreeing counts of what needs attention, and “Your budget” shows one invoice against a project total two taps away.

    F41

    Size M. No backend.

  • SP-17

    A decision can be deferred, and shows the colour

    A colour decision presents two text-only cards, and there is no way for a client to say “not yet.”

    F44F59

    Size M. No backend, deliberately — deferring routes through the existing thread, not a new status.

  • SP-18

    Signals that are not real come down

    The room’s AR stat can never be anything but zero, and one editorial story stays marked unread through every relaunch.

    F64F46

    Size S. No backend to take the signals down.

  • SP-19

    Nothing covers the button; nothing is smaller than a thumb

    The Companion’s Hearth paints an opaque band over “Sign proposal,” and the status bar draws over invoice numbers and proposal titles.

    F49F114

    Size M. No backend.

  • SP-20

    Sign Out, and a way to close the account

    There is no way to sign out of this app — the Settings row to Account draws a chevron and does not navigate.

    F45App Store 5.1.1(v)

    Size S for sign-out, M with deletion. Sign-out: none. Deletion: one new edge function.

Across all twenty, the backend cost is one migration, one new edge function, notification_log writes on two existing paths, one confirmation email on an existing chokepoint, and a portal-side route. Everything else is iOS — the client app is behind its own backend, not ahead of it.
