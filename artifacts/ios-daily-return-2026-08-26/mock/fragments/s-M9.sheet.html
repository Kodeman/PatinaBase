s-M9 · Live Activity: a delivery · screen sheet
PurposeDraw the one thing a Live Activity is actually for — a delivery window — so the cost of it can be seen and judged. Neither direction ships this in wave one: Direction A declines Live Activities outright, because its order’s status derives from line states no vendor has acknowledged; Direction B admits one only at W6, once a line is really shipped and an ETA is real.
Entry pointsStarted by the app when a designer-sourced order reaches shipped; shown on the Lock Screen and, compact, in place of the Dynamic Island.
ComponentsNew: an ActivityKit activity, its per-activity push token, and a liveactivity push-type branch in apns-send — which today resolves device_push_tokens and sends one alert shape to a single topic. Without that branch the activity updates only in the foreground and goes stale when the app is closed. Existing: fulfillment_orders and fulfillment-notify, which already sends the six transitions to a homeowner’s device.
Copy“PATINA · DELIVERY” · “Heirloom Oak Dining Table” · “Nordic Atelier · white-glove delivery, Living Room” · step names “Confirmed”, “In production”, “Shipped”, “Delivered” — four of the six transitions fulfillment-notify already sends (the others are an ETA change and a substitution). “Arriving 2–4 PM” and the compact “2–4 PM” are [example].
Datafulfillment_orders and its line states, pushed by fulfillment-notify — which fires only when an admin operator presses send, and only on the designer-sourced rail, never on a client’s direct order. No table carries a delivery window or an ETA today, which is exactly why both directions defer this: the bar and the step marker are real, the clock face on it is not.
StatesNo ETA — the activity does not start; the record and the push carry the transition instead. Shipped without a window — the step advances, the time line is absent rather than guessed. Stale — without the push-type branch the activity holds its last state; it must never show a countdown it cannot update. Ended — the activity is dismissed on delivered.
InteractionsTap → the order. Analytics: live_activity_started, live_activity_opened — new.
TieractiveProject only, and only for a designer-sourced order that has really shipped.
Callouts1 · the compact activity replaces the Dynamic Island — the only Patina surface that changes without the app being opened. 2 · the arrival window is example copy: no column holds it. 3 · the steps are the transitions the fulfilment rail already emits; nothing here invents a status. 4 · and this is the one mock in the set that neither direction proposes for wave one — A declines it, B gates it at W6 behind a real ETA and an ActivityKit push token.
New vs todayAll of it, and it is the most expensive surface in the set for the least verified data. It is drawn so the cost is legible, not because it is recommended.
