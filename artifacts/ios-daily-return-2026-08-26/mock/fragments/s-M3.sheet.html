s-M3 · Saved · Boards · screen sheet
PurposeA board that actually holds pieces. Today Boards is the default tab, it is the first thing a new reader sees, and it can never fill: addToBoard is not called from anywhere in the app.
Entry pointsThe Boards tab · the Companion’s “Saved” row when at least one board exists.
ComponentsExisting: CollectionsView.boardSection (name, mono count, three-up grid of ProductCard tiles), the New Board alert. New: the wiring — the save path calls addToBoard, or Boards comes out of the app until it holds something.
Copy“Saved” · “Boards” / “All items” · board name “Living Room” [example — a board name is the reader’s own] · “3 items” · tile prices “$4,200” / “$2,100” / “$1,450”. The empty state keeps its shipped copy: “No boards yet” / “Save pieces from recommendations to create your first board” / “Create Board”.
DataBoardModel in the local store; tiles resolve through itemsByProductId to the same TableItemModel rows the All items tab reads. Boards are device-local today — a remote mirror is direction work, not this plank, and the deck should not imply one.
StatesNo boards — the empty state, and All items becomes the default tab. A board with no items — the head draws, the grid does not. Tile image missing — the Strata placeholder, with the price still legible.
InteractionsTile → piece detail. + → New Board alert (existing, unchanged). Analytics: board_created, board_opened — both new.
TierEvery tier, including guest. Nothing here is designer-gated.
Callouts1 · Boards is the default only once a board exists (SP-12). 2 · the count is the board’s own, and it can be non-zero because saving now writes to the board. 3 · a tile with no image is the honest placeholder, price still readable. 4 · + is the shipped board-creation alert — the only part of Boards that works today.
New vs todayEverything that makes a board fill. The screen, the head, the grid and the alert exist; the path from a save to a board does not.
