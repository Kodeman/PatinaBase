# UX critique — the doc in project & install phases (Opus, 2026-08-13)
*(Adversarial synthesis of 01-code-map.md + 02-prod-inventory.md. Screenshot set from phase 1 was unusable (terminal captures); themes stand on structure + verified text findings. Evidence letters (a)–(k) refer to the field findings in 02-prod-inventory.md.)*

## Themes

### T1 — The doc's orienting devices contradict each other · CRITICAL · HIGH
Header chip, schedule spine, left-rail active section, and desk cards make simultaneous, differently-computed claims about "where this project is" with no arbiter. Evidence: (a) "Week 2" vs "NO ACTIVE OR DELAYED PHASE IS CONFIGURED"; (b) active-but-empty projects; (c) Mara Whitfield ×3. A document is trusted because it is ONE record; two lines disagreeing turns it into widgets sharing a URL, and designers go back to their spreadsheet. Principle: status legibility / single source of truth. Fix direction: elect the schedule spine as the canonical status organ; header chip and desk cards render ITS output verbatim.

### T2 — Install is not a real mode · CRITICAL · HIGH
Install composes almost nothing new: same FF&E table (`mode="install"`) + unfolded CareBand. The most operationally distinct week gets the least distinct composition. Punch lives inside the schedule. Evidence: structure; (e) Harper Vale closed with 0-of-1 installed/uninvoiced. Install's unit of work is a room and a day, not a line item and a decision. Principle: mode fidelity / task-form matching. Fix direction: give install its own composition — lead with room-by-room state, promote punch to a peer band, defer Care until close clears.

### T3 — Financial instruments stacked without hierarchy · MAJOR · HIGH
Design Authority / Working Budget / Authorizations & Trade Scopes / Accounts are four different KINDS of thing (permission, plan, commitment, ledger) in a dependency chain, rendered as equal siblings in near-identical typography. (h), compounded by (f) "$ from – to $0". Principle: visual hierarchy expresses semantic hierarchy. Fix direction: nest into one money region, one dominant headline figure, three subordinate dependent tiers.

### T4 — No fleet view; the desk answers a different question · CRITICAL · HIGH
No surface lists all projects with phases (k). Desk = triage ("what is on fire"); doc = "this job"; the portfolio question ("what's the state of my book?") has no home. (j) REVEAL 3 MORE FOLIOS inert. This is also WHY (b) is tolerable to the system — nothing ever displays "three active projects have no schedule composed." Principle: overview-first / orientation. Fix direction: add a roster tier above the doc — every engagement by phase — and reposition the desk as the exceptions view over it.

### T5 — Empty modules erode the document metaphor · MAJOR · HIGH
Mood boards + plan room empty on EVERY project (g), regardless of maturity; "$ from – to $0" (f); "Name a phase…" still offered after Completion (i). Undifferentiated blanks destroy emptiness-as-signal; a doc that keeps offering authoring affordances never reads as finished. Principle: progressive disclosure + meaningful empty states. Fix direction: composition responds to phase and content — never-populated bands collapse to one quiet line; authoring affordances retire when their phase passes.

### T6 — The document leaks its own machinery · MAJOR · HIGH
"2 ACTIVE PHASES NOT CLASSIFIED TO A CANONICAL STAGE", "NO TEMPLATE PROVENANCE RECORDED", "NO ACTIVE OR DELAYED PHASE IS CONFIGURED" (d)(a) — internal taxonomy in the reading surface, same caps register as legitimate status, no remedy offered; reads as errors the designer caused. Principle: speak the user's language. Fix direction: demote machine-state notices to a single collapsed "needs setup" affordance on the section header.

Cross-cutting (T2/T5): **forcing functions** — a state that must not persist (uninstalled, uninvoiced, unclosed) needs a stop, not a silent field.

## Install-as-a-mode assessment

What install week demands vs what the composition gives:
1. **Room-by-room state** — "Primary bedroom: 8 of 11 placed, 2 damaged, 1 not shipped" is THE question; a line-item table can't answer it without mental grouping. Largest single gap. (MAJOR–CRITICAL)
2. **Punch as first-class** — generated during the walk, gates final payment, yet nested inside the schedule. (MAJOR)
3. **No forcing function at close** — (e) proves it: close was a state change, not a checklist that had to clear. Costs real money. (CRITICAL)
4. **Care unfolds too early** — the ONLY structural signal of install points at the phase after it. (MAJOR, MEDIUM conf)
5. **Recap tail dilutes the working surface** — install sits at the bottom of a long scroll under read-only recaps + empty mood/plan bands; worst signal-to-scroll at highest urgency. (MAJOR)
6. **"Book closed" + "Care ongoing" + uninstalled item displayable, never reconciled** — T1 localized to the install/care boundary. (MAJOR)
Also unmet: arrival/staging logistics (time-and-location model vs specification model), day structure / call sheet as an install instrument.

**Verdict**: install is a label on project mode, not a mode. Highest-leverage compositional gap in the doc.
