## 1. Middleware redirect map

**`apps/client-portal/src/lib/retired-routes.ts`** (new) — the map, as one pure function
`retiredRouteTarget(pathname)`. Kept out of `middleware.ts` so it is unit-testable on its own and so

**`apps/client-portal/src/middleware.ts`** — three changes:

1. The map, applied as **308** with `redirectWithCookies(target, 308)`, placed **after** the
   sign-in gate and the role gate. Order matters twice:
   - After the sign-in gate, an unauthenticated visitor is sent to
     `/auth/signin?callbackUrl=<the OLD path>`, comes back to it, and is folded then — so the anchor
     survives the round trip. Folding first would hand sign-in a bare `/`.
   - After the role gate, a designer/manufacturer who lands here still gets `/wrong-portal`.
2. `/preferences/unsubscribe` (and its trailing-slash form) added to the public allowlist. It is the
   landing page `GET /api/unsubscribe` redirects to *after* applying the token; gating it bounced
   signed-out recipients into a sign-in wall in front of an outcome page for an action already taken.
3. Sign-in destination `safeAuthReturnPath(..., '/projects')` → `safeAuthReturnPath(..., '/')`.

### The map

| Old path | Lands on |
|---|---|
| `/today` `/decisions` `/decisions/<id>` `/reviews` `/scans` `/scans/<id>` | `/#doorstep` |
| `/projects/<id>/reviews` `/projects/<id>/reviews/<editionId>` | `/projects/<id>#doorstep` |
| `/proposals` `/proposals/<id>` `/proposals/<id>/sign` | `/#door` |
| `/invoices` | `/#letterbox` |
| `/invoices/<id>` | `/?invoice=<id>#letterbox` |
| `/budget` | `/#ledger` |
| `/documents` | `/#mat-papers` |
| `/orders` | `/#road` |
| `/messages` `/messages/<threadId>` `/inbox` | `/#note` |
| `/account` `/preferences` `/settings/*` | `/#mat` |
| `/projects` | `/` |

Rules the map obeys:

- **Project id carried when the old URL had one.** Only `/projects/<id>/reviews*` did; everything
  else targets `/`, which resolves to the client's active project.
- **Original query preserved**, and the fragment appended *last* — a URL's hash always follows its
  query. The plan's shorthand `#letterbox?checkout=…` is not a valid URL; the emitted shape is
  `/?checkout=success&session_id=cs_1&invoice=inv-1#letterbox`, which is what the letterbox actually
  reads (L2's `checkout-return.ts` contract).
- **`invoice=<id>` added** when folding `/invoices/<id>`, so a receipt email sent months ago opens
  the letterbox on the invoice it was about rather than the default one. `order=` already rides the
  original query. Same param names L2 chose for `create-checkout-session`.
- **Ids are validated** (`/^[A-Za-z0-9_-]+$/`) before being interpolated into a `Location` header; a
  path segment that is not a plain id falls back to `/`.
- **Not mapped on purpose:** `/preferences/unsubscribe` (public, kept) and `/invoices/<id>/print`
  (the printable invoice has no in-page equivalent — see Conflicts).

## Conflicts / rulings needed

1. **`stripe-webhook`'s invoice links were NOT repointed**, against the plan's End state
   ("`stripe-webhook` … invoices → `#letterbox`"). Reason: the Patina iOS app's
   `Patina.entitlements` claims `applinks:client.patina.cloud` and the live AASA publishes
   `/invoices/*`, `/proposals/*`, `/decisions/*`; `DeepLinkHandler.route(forUniversalLink:)` maps
   exactly those three to native screens. Repointing an invoice receipt to `/projects/<id>#letterbox`
   — a path the AASA does **not** claim — would drop that email out of the app and into Safari, and
   would leave `invoice-send` / `invoice-reminders` / `proposal-nudge` /
   `proposal-sign-confirmation` (all unnamed by the plan) pointing somewhere else, which is worse
   than either choice alone. With the middleware carrying `?invoice=<id>` through the 308, the web
   experience is now identical either way, so keeping the AASA-claimed shape costs nothing and keeps
   iOS whole. **If Fable rules the other way, the change is four one-line edits plus adding
   `/projects/*` to the AASA — the latter is a product decision (it would make the app intercept
   every project link) and is out of this lane's scope.**
2. **`/invoices/<id>/print` is not mapped**, per the End state's exact enumeration — but the same
   plan's Deleted list names the whole `src/app/invoices` tree, which would take `print` with it and
   404 the printable invoice. R2a needs a ruling: keep `print` (and move it out of the deleted tree)
   or fold it too.
3. **`/projects/<id>/scope-change/new` and `/projects/<id>/scope-change/<changeId>` are not mapped** —
   they are in the plan's Deleted list but absent from its redirect map. They will 404 after R2a
   unless the map grows two rows. They carry a project id, so the natural targets are
   `/projects/<id>#doorstep` (or wherever the completion lane absorbs the change-request act).
4. **`/preferences?token=…`** — the preference-token apply is a `POST /api/preferences/apply-token`
   made from the `/preferences` page, which now folds to `/#mat` (the token survives in the query).
   The mat has no preferences UI yet. Whoever absorbs preferences must read `?token=` on the mat, or
   one-click preference links go dead at cutover.

## Advisories

- `ThresholdRouteCollapse` (`src/app/layout.tsx`) still does a client-side `router.replace` for the
  nine old routes. The middleware now answers first, so it never fires — dead weight until R2b
  deletes it, but harmless.
- 308 is cached hard by browsers. Intentional (the addresses are gone for good), but it means a
  rollback of the portal Worker does **not** un-teach a client's browser. Worth a line in the ship
  runbook.
- `public/sw.js` (committed workbox build output) is `NetworkFirst` over `^https?.*` with a 30-day
  window. The Cloudflare build ships no service worker (`next.config.js` skips `withPWA` when
  `OPEN_NEXT=true`), so this only affects stale installs — but a stale install can serve a cached
  old-route HTML past the cutover.
- `apps/client-portal/wrangler.jsonc` still pins `NEXT_PUBLIC_FLAG_OVERRIDES: "threshold:false"`.
  Not this lane's file (the plan assigns it to the flag removal), but the redirect map lands clients
  on `/` and `/projects/<id>`, which render the old surface while that pin stands.
- `deep_link` values already written into `notification_log` rows (`/decisions/<id>`,
  `/invoices/<id>`, and `00280:93`'s designer-shaped `/portal/billing/invoices/<id>`) are historical
  data; the map answers the first two and cannot answer the third, which has never resolved on this
  portal.
