# Design review 6 — the acceptance walk's design defects (US-19 FR6)

**Headline: one high, and it is a rule-of-names failure, not a missing feature.** On the new named-client proposal paper (Tanaka) two different controls are both called *Nudge*: the band's own act, whose landing id is attached to nothing, and the proposal watch's one-press reminder, which emails the client with no arm. Everything the band promised on Aspen (a composer, `Waiting on {first}: …`) exists in code and is never reached on a proposal paper. The fix is to make the composer the one `Nudge {first}` on the paper and to give the reminder its own name and an arm. The rest of the walk's list is medium and low, and most of it is conformance to rulings already on the record (D2's phone form, P-2, D1's maker word), not new design.

- Tree ruled: `main` at `8f984bdba` (the walk, SQ-504). F5-1 (`ebc24d554`) is ruled from its DESIGN-Q text, not from its diff. No browser; code and the walk's JPEGs only.
- Authority: `rulings.md` D1–D11; `design-review-1.md` R1–R42; `design-review-2.md` P-1, 499-1; `design-review-3.md` P-2, F3-2, F3-16, §4-9 (the Esc law); `design-review-4.md` 520-1, 520-3, 521, 522-1, 522-2, 524-d/f, §4-3, §4-4, §4-7, §4-9; `design-review-5.md` F5-1…F5-10, 530-3, 531-1, §3-1. ## 1. Rulings

### D1 — Tanaka: the band's `Nudge Mei`, the region's `Nudge Mei Tanaka`, the one-press reminder (HIGH)

What the code does, read on main:

- `lib/document/act-names.ts:367-378` — `ownAct('proposal', {proposalState: 'sent'})` returns `Nudge {first}` with `targetId: ACT_TARGET_IDS.proposalNudge` (`'document-act-proposal-nudge'`). That id is attached to **no element** (the only reference is the table itself), so `page.tsx:2569-2580`'s `activateDestination({kind: 'anchor', focusId})` falls to the proposal region's `<div>`. The same shape as story log #7's `piecesHead`.
- `page.tsx:1889-1931` — the need rows that give Aspen its composer landing (`overdue_decision` → `landAct(ACT_LANDING_EVENTS.composeMessage, {named})`) are built **only when `row.engagement_kind === 'project'`**. A proposal paper has no need rows on its band, so its two overdue decisions never rank (they stand only in the margin) and Next is always the own act.
- `components/document/proposal-instruments.tsx:151-221` — the region's control is `DocumentAction actionKey="nudge-client"` printing `Nudge {familyLabel(clientName)}` (the full name, `Nudge Mei Tanaka`); `onNudge` calls `useNudgeProposal().mutateAsync` at once (R71's proposal reminder, an email) and prints `Reminder sent to {family}.`; the watch then prints `Nudged 8 October · reminder sent to Mei Tanaka.` `components/document/worktable/finalize-head.tsx:57-127` carries the same control for legacy `document_kind`.
- `components/document/letterhead-instruments.tsx:458-473` — the composer listener for `document:compose-message` exists and opens the Message composer with `named` (the `Waiting on {first}: …` line), when `oneVoice && canSendNote`. Mei is a login, so on Tanaka it would answer; nothing dispatches it.
