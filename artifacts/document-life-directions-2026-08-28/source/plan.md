# Designer Portal — "Bring it to life": three UI directions deck

## Context

Designers report the Patina designer portal is **too flat — everything blends together**. The ask: a senior-UI-designer review of the current portal and **three UI-only directions** (no UX / workflow / IA / copy / interaction changes — same routes, same components, same acts) presented as an HTML deck the Patina team can weigh in on. Deliverable = the deck (published as an Artifact) + a program folder `artifacts/document-life-directions-2026-08-28/`. **No product code changes in this program.**

Rulings taken: **lean pipeline** (~10 subagents, not the 25-agent house pipeline); the deck **may pose a bounded D4 (shadow) amendment as a ruling question** — prose only, in the questions section; no mockup shows a shadow; no direction depends on it.

Fable orchestrates; all execution goes to subagents (Opus = design authoring/critique, Sonnet = research/build/QA, Haiku = mechanical). Fable publishes the Artifact and reviews every gate's output.

## What the exploration established (the diagnosis the deck argues)

Everything below is re-measured on a fresh build in Phase 1 before the deck quotes it.

- **One tonal register.** `apps/designer-portal/src/app/globals.css` (`:root` 8–137) defines 11 surface tokens, but the three that carry the page — desk ground `#FAF7F2`, document paper `#FCFAF6`, card/drawer `#FFFFFF` — sit within **1.07:1** (2.7 L\*). The DocSpine wash (`src/components/document/doc-spine.tsx:44`, pearl @28%) is **1.04:1** against the paper. The Studio Drawer (`studio-drawer.tsx:289`) is the same white as a card. `--text-muted`/`--text-subtle`/`--text-faint` are all `#65594E`.
- **One type register.** ~1,100 of ~1,700 sized elements on Document surfaces are 8–12px; DM Mono caps ×1,038 vs Playfair ×268; largest Playfair in the shell = 1.7rem (30.6px at the 18px root). 82 arbitrary sizes, 15 radii.
- **One rule.** 504× `border-[var(--color-pearl)]`; section heads share one italic 14–16px serif. Priors already on record: `docs/design/doc-polish/deck.html` ("…all claim the same visual weight"); `artifacts/document-wayfinding-directions-2026-08-25/research/25-panel-p1.md:482` ("Same tint, same hairline rule, same weight"); `artifacts/doc-ux-review-2026-08-13/03-ux-critique.md:12` (T3 "stacked without hierarchy").
- **Color only as pale tabs.** Hover fill = clay @6%; `StatusChip` (`status-chip.tsx`) = dot + 10px mono, no fill.
- **No material.** Zero product/room imagery on desk or document. Honest scope: `products.images` is populated (17/21 local rows) but `project_ffe_items` has no image column and local lines have `product_id IS NULL` — thumbnails are real only where a line links a catalog product; room-scan thumbs are shape-only locally.
- **Canon.** D4 (`docs/design/the-document/DECISIONS.md:15`): no shadows, CI lint `apps/designer-portal/eslint.config.mjs:67–140`. One sanctioned exception: `.folio-face` drop-shadow (R72, `globals.css:216–230`). `apps/designer-portal/CLAUDE.md:21–23`: typography-first, "not cards-within-cards, not tab bars". I151 (2026-08-26) added `--color-*-ink` tokens + `src/lib/document/__tests__/contrast.test.ts` (WCAG math at :82–100; paper-ink vs charcoal-pigment rule at :133–152).
- **Evidence caveat.** The 2026-08-25 desk capture shows folio cards; `desk-roster.tsx` has since replaced them ("never a card"). Fresh baselines are mandatory.

## The three directions (design lead's brief — the author executes, the critic tests)

All three keep every route, component, interaction, label and IA identical, expressed as **token deltas over the real `globals.css`** + component recipes so feasibility is honest. Same specimen data in every lane (reuse the vetted specimen in `artifacts/document-wayfinding-directions-2026-08-25/source/instruments.md` §8). Names follow house convention (`Direction A — <Title>`), Patina lexicon, no adjectives.

**A — Ink on Paper** *(type + tonal contrast; inside D4; lowest cost)* — a real type scale (Playfair section heads 22–28px, document title ~40px, body floor 14px, mono labels 11–12px and fewer of them); a three-weight rule system (hairline / 1.5px charcoal rule / double rule) replacing the single pearl hairline, `.doc-region-rule` + StrataMark as the section device; three paper stocks ≥1.15:1 apart (desk ground / document paper / spine+margin stock); charcoal `#2C2926` primary text, `-ink` accents, three real muted steps. Signature: the section head. Ships as ~20 token edits + a class sweep.

**B — Honest Materials** *(color, tint, imagery, texture; inside D4)* — paper tinted by document movement (Brief / Proposal / Project / Install / Care on their own stocks from the six `--phase-*` hues at 4–8%); saturated folder tabs; **filled** status chips (pigment fill + `-ink` text); letterhead and red-letter zone on a charcoal band; 40–56px product thumbnails on catalog-linked FF&E lines, roster rows and Library; 2–3% paper grain. Signature: the tinted movements. Risk the critic must test: reads as "dashboard".

**C — The Dark Desk** *(inversion; depth via value contrast — D4's own mechanism)* — charcoal grounds for Studio Drawer, DocSpine and MarginRail; the paper reads as a sheet on a dark desk. Precedent: MobileBar (`mobile/mobile-bar.tsx:216`) and sub-1180 LogStrip (`log-strip.tsx:86`) are already charcoal; pigment inversion rule already in `globals.css:28–33` + `contrast.test.ts`. Clay/sage base pigments on dark; one warm clay rule where paper meets desk. Signature: the paper edge. Risk: heavier at night; 390px.

**Ruling question (not a direction):** admit one tokenized ambient elevation (e.g. `--elevation-sheet: 0 1px 2px rgba(44,41,38,.08)`) for lifted sheets/margin chips/drawer, citing R72. Written in `source/amendment-elevation.md`; appears only in the questions part.

**Shared planks SP-01…** (all three adopt identically; never add surfaces or move regions): 14px body / 11px mono floors; collapse the three-same-value muted tokens; a rule-weight token set; `-ink` for every pigment-as-text; StatusChip fill variant; hover fill above 6%; drawer ground distinct from cards. Each plank cites F-ids.
