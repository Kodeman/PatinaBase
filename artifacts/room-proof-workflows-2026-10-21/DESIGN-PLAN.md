# A working studio, through the Room Proof

The brief extends an approved direction into the current designer portal's actual work. It does not ask for another visual direction or a production implementation.

## Material and hierarchy

Paper #FCFAF6, stock #E8E3DB, charcoal #2C2926, quiet ink #65594E, annotation blue #355267, agreement green #3E5145. Patina's existing Playfair headings, Inter working text, and restrained DM Mono reference notation. Work text is normally 13–15px; supporting metadata stays readable.

## Structure

The studio has a desk, rooms for sustained work, and books for operations. The sample project retains the expansive room image and selected object's working margin. Other work uses its appropriate composition: product shelf, material specimen, issued decision paper, schedule, financial ledger, person record, and specification book.

```
Studio overview → project document → room / pieces / evidence
                         ↓
                issued client approval
                         ↓
             separate financial authority → order draft + holds

Resource library → configured piece → Add to project
Timesheets → eligible unbilled work → invoice draft → Accounts
Contacts / Inbox → the underlying project, person, or order
```

The presentation explains the mapping and its limits. The mockup supplies thirteen connected views, local sample state, direct URLs, keyboard access, and a guided route. Source labels and technical evidence belong in the presentation, not in the designer's ordinary working surface.

## Review against the brief

The earlier proposal's distinctive idea remains: the room is an entrance into actual work. Expanding it into a generic dashboard would lose that idea. This version instead gives dense financial, contractual, and operational work its own readable document form; not every action is forced onto a photograph.

The current source has no legacy `(portal)/portal` tree. Mapping is grounded in the Document routes and components at repository baseline `98c6baa69`. Source presence is not a claim about enabled production flags or live data. Formal design approval, purchase authority, money received, vendor payments, and order release remain separate facts.
