# Specimens technical review — client-house.html, designer-desk.html, decision-moment.html

Fresh-context adversarial pass. Renders were re-run independently into
`$TMPDIR/specimen-review/` (Chromium via `tools/render.mjs`, sandbox disabled
per the tool's own README note — `MachPortRendezvousServer: Permission
denied` inside the default Bash sandbox) at 1440 and 390 for every declared
meta-strip state, plus `--dark` and `--reduced-motion` at 1440, plus
`--full false` viewport captures used specifically to separate real defects
from the documented full-page stitching artifact. All 34 PNGs were opened and
inspected; all console.json files were parsed programmatically; static
regexes and small Playwright scripts were used for the mechanical checks
(hex literals, font loads, tab order, contrast, hold-timing, anchor
resolution). Contrast is computed with the standard WCAG relative-luminance
formula, not eyeballed.

## Verified OK (leave alone in the fix pass)

- **Console / overflow**: all 32 render captures (client-house ×8, designer-desk ×12, decision-moment ×12) report zero `errors`, zero `warnings`, `horizontalOverflow:false` — clean across every state, both widths, dark, and reduced-motion.
- **Fonts**: `document.fonts` confirms real loaded faces for every weight actually used — DM Mono 400/500, Inter 400, Playfair Display 500 (normal) and 400 (italic). No file requests or renders a synthesized bold; static scan found zero `<strong>`/`<b>` tags and no `font-weight` value other than 400/500 anywhere in any of the three files. No serif-fallback or missing-font rendering observed in any screenshot.
- **Static "do-not" list**: zero occurrences across all three files of `box-shadow`, `text-overflow`, bare `disabled=` attributes, `opacity:.5`/`0.5`, `@keyframes`, `✓`, and `PATINA` (all-caps wordmark). Only lowercase "Patina" appears, once each in client-house.html and decision-moment.html, inside the permitted colophon line "Sent through Patina."
- **Hex literals**: the only hex literal found outside a `:root` block in any file is `#1F1D1A` (`.act--terminal:hover`) in client-house.html and decision-moment.html — the literal explicitly allowed by the SPEC's own "exact CSS" block. designer-desk.html has zero. No stray hex literals anywhere else.
- **`lang="en"`**, **exactly one `h1`** (all three files), and **heading order with no skips** (h1→h2→h3 throughout; h3→h2 "step back" transitions are fine and occur only where a new sibling section starts) — confirmed via regex + manual DOM trace for all three files, including dynamically-injected headings (roster stage `h3`s, record-block `h3`s in noted/accepted states).
- **Images**: client-house.html's single `<img>` (the embedded photo, see T05) has `alt=""` with an adjacent caption carrying the meaning ("Study · photographed by Local Dev Studio · 3 September 2026") — correct per SPEC A13's "`alt=""` when the caption carries the meaning." designer-desk.html and decision-moment.html contain zero `<img>` tags (SVG only), matching the "no photograph" declaration in their meta strips.
- **Meaningful SVGs**: every SVG that conveys information carries `role="img"` + a descriptive `aria-label` (letterbox, section drawing, wall elevation, road, per-piece plates, board thumbnails). Purely decorative SVGs (pole-mark triangle, doorway glyphs) are correctly wrapped in `aria-hidden="true"` rather than given `role="img"`.
- **Dark-mode token completeness**: all three files define dark tokens both ways — `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {...} }` and `:root[data-theme="dark"] {...} }` — verbatim and complete in every file.
- **Contrast (light mode)**: `--oak` on `--paper` = 4.20:1, on `--paper-doc` = 4.30:1 (matches the SPEC comment exactly); `--ink-faint` on `--rail` (aria-disabled terminal ink) = 5.32:1 (matches SPEC comment exactly); `.caption`/`.t-meta` ink (`--ink-subtle`) on paper = 7.54:1; white stage-plate labels = 5.22–8.20:1 (matches SPEC's documented range exactly). All pass their respective 3:1/4.5:1 thresholds.
- **Contrast (dark mode)**: `--oak` dark on dark paper = 5.33:1, on dark paper-doc = 5.61:1; `--ink-faint` dark on dark rail = 5.55:1 — all pass. (Stage-plate labels are the one dark-mode failure — see T01.)
- **Keyboard reachability & focus ring**: every `.act` in every file (including `aria-disabled="true"` gates) is reachable by Tab and shows a visible 2px outline on focus. client-house: 25 tab stops in sensible top-to-bottom order. designer-desk: 61 tab stops, correct order (state → 3 header acts → margin-note dismiss → facets → day's-line links → interleaved roster name/Open per row → studio index → bottom bar). decision-moment: 13 tab stops in the default state (state switcher → chips → Note/Ask → sign field → Accept → legend demo acts).
- **`aria-disabled` acts stay focusable and announce their reason**: live-tested in both client-house.html (`#gate-act`) and decision-moment.html (`#acceptAct`) — pressing Enter while unmet keeps focus reachable, moves focus to the name field, and writes "Type your full name to accept." into the page's `role="status"` line in both files.
- **decision-moment hold timing**: live-tested — holding Enter on the armed Accept act for 300ms and releasing correctly cancels (no record committed, `is-holding` class removed); holding for ≥900ms correctly commits (record block rendered). A 300ms release does not fire the 900ms `setTimeout` in either case.
- **decision-moment notch-fill**: `wall.classList.add('is-closed')` on accept correctly sets `.notch-fill` to `display:inline` with `fill:url(#wallHatch)` (confirmed via computed style, not just visual guess) — the notch is programmatically "closed" to match the surrounding wall's hatch pattern.
- **designer-desk 43-job proof**: JOBS array sums to exactly 43 (8+5+7+6+9+5+3) with exactly one `m:'urgent'` entry (Vandersteen) — confirmed by array inspection and cross-checked against the rendered `43jobs` screenshot ("43 LIVE · 1 OVERDUE", exactly one terracotta-marked row). 16-job baseline sums to 16 (see T02 for the Project/Hollenbeck caveat) with exactly one overdue. The `Only what needs me` facet filters to exactly 7 of 16 (matches SPEC's explicit "(7 rows at 16 jobs)"), and both facets visibly change the DOM/grouping (verified in `designer-desk-needsme-*` / `-byperson-*` screenshots).
- **client-house landmark & story-pole links**: all 7 unique `#`-anchors used across the landmark ledger and story pole resolve to real IDs in the document (`story-pole`, `changed`, `letterbox`, `wall`, `previously`, `road`, `study`) — none are broken, confirmed by script (see T06 for a content-quality caveat on where several of them point).
- **designer-desk anchors**: all dynamically-generated `#job-*` and `#stage-*` anchors resolve at runtime (script-checked); the only non-resolving `href="#"` instances are the intentionally out-of-scope "doorway" links (Library, People, Orders, etc.) representing app areas outside this specimen's scope — not a broken-link defect.
- **Quiet-day / After-acceptance states (client-house)**: "What needs you" landmark and the `#wall` gate are correctly omitted (via `display:none`, which also removes them from the tab order and accessibility tree — a true "omission," not a disabled control) in Quiet day; the Study piece stamp correctly flips `Installed`→`Accepted` and the doorstep copy correctly re-reads in After acceptance; the money block, letterbox, and Previously correctly persist in all three states.
- **decision-moment states**: Noted/Accepted correctly replace only the acts block while the money table/ledger stays on screen above the record ("a record that shrinks is not a record"); Save-failed correctly shows a `role="alert"` panel with focus moved to Try again, preserves the finish selection, and leaves the original acts in place.
- **File sizes**: client-house.html 341KB (embedded photo, see T05), designer-desk.html 38.5KB, decision-moment.html 33KB. The embedded JPEG is used exactly once (`data:image/` count = 1).
- **One family per figure / money typography**: the single announced money figure (`$4,060.00` in client-house) correctly uses `.t-d2` (Playfair); every other aligned figure across all three files correctly uses `.t-money` (DM Mono, tabular-nums, `.02em` tracking) — no block mixes three type families for one payment.

## Top five findings

1. **T01** (P2) — designer-desk.html dark mode: white labels on the Brief/Discovery/Direction stage plates fall to 3.90:1 / 4.20:1 / 4.46:1, below the 4.5:1 text-contrast floor.
2. **T05** (P2) — client-house.html embeds the Study photograph as a 295KB base64 data URI instead of a relatively-referenced `room.jpg`, contradicting SPEC §B and bloating the file ~9x.
3. **T03** (P2) — decision-moment.html never announces "Noted"/"Accepted" completion into the `role="status"` line — a screen-reader user gets no confirmation that $2,980 just moved.
4. **T02** (P2) — designer-desk.html's 16-job baseline includes "Hollenbeck residence" in Project (4 jobs, not the 3 named in SPEC §B), borrowing a name the spec reserved for the 43-job proof only.
5. **T04** (P3) — client-house.html's `aria-disabled` CSS uses a presence selector where the SPEC's "exact CSS" and decision-moment.html both use a value selector (`[aria-disabled="true"]`) — currently harmless but an unforced spec/cross-file deviation.
