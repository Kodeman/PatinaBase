## Patterns

There are **27 inventory rows**. **10** are marked yes for pre-click knowledge, **12** partly knowable (data can indicate a blocker, but authority, stale state, or the actual RPC/provider outcome cannot be promised), and **5** no. **At least 7 destinations** need product follow-up or have no guaranteed direct action: the unpriced FF&E notice, studio roster/access, account-band invoice folio link, composer rollback reconciliation, and stale/failed invoice destinations called out above. “None” in the JSON identifies a missing act; listed route/control destinations are not proof that the current screen links to them.

Shared roots: RPC/PostgREST failures are often thrown unchanged from `use-invoices.ts` and surface via the global MutationCache unless the caller has opted into inline handling. Composer mutations opt into inline routing but catch and print raw messages in a bespoke box, so routing alone does not translate copy. The account-band milestone hook likewise exposes raw RPC error text. Edge sends prefer server `detail`/`error`, which can be a machine code. `handleApiError` normalizes Axios/network/auth and one FF&E constraint but generally passes unknown PostgREST object messages through; `react-query.ts` determines whether the result is a toast, inline suppression, silent handling, or auth route. RPCs own distinct guard reasons, yet their raw strings share the same screen-level copy defect.
