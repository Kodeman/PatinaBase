### W4-R2-06 — note — **ruling owed** · confidence high (measured) · extends the still-open W4-R1-05
**The project ↔ internal conversion is open in **both** directions and, in one of them, an
owner/admin can silently zero a **teammate's** authorized, rated hour.**

*Location:* `00612`'s `internal_time_owner_admin_update` + `00605`'s
`time_entries_owner_admin_update`, with `00613`'s short-circuit doing the repricing. Round 1 named
the internal → project direction (W4-R1-05) and `00613`'s banner (`:59-67`) names only the
member's own project → internal direction.

*Finding, measured (two transactions, my own fixtures, live 15000¢ card).*
1. **project → internal, by the OWNER, on the MEMBER's hour.** Before:
   `authorized / 15000 / 15000`. `UPDATE … SET project_id = NULL, studio_id = <studio>, billable =
   false` as the owner → **1 row**; after: `project NULL / nonbillable / rate NULL / amount 0 /
   billable f`. A $150.00 unbilled, authorized hour of somebody else's work is written down to zero
   in one statement. One `audit_logs` row is filed (and, thanks to the round-1 fix, the studio can
   now read it).
2. **internal → project, by the OWNER.** A 45-minute internal hour becomes
   `authorized / 15000 / 11250` — billable, invoiceable client time — and the row keeps its
   now-meaningless `studio_id`. RLS cannot refuse this: permissive `WITH CHECK` arms are OR'd
   independently of `USING`, so no single policy has to be true of both the old and the new row.

The authority is not novel (an owner may already delete or re-duration a member's hour through
`00605`), and no surface offers the act, so this is a stance to record rather than a defect. But
HT-15's "internal time is never billed" is true **per row-state**, not per hour, in both
directions and for two different actors, and only one quarter of that is written down.

*Exact fix.* A ruling, then one of two code paths. If conversion should be refused, RLS cannot do
it — it needs a trigger leg, most naturally in `guard_commercial_time_entry_derived_fields`:
```sql
IF (OLD.project_id IS NULL) IS DISTINCT FROM (NEW.project_id IS NULL) THEN
  RAISE EXCEPTION 'internal time and project time cannot be converted into one another'
    USING ERRCODE = 'check_violation';
END IF;
```
(`aab_` already watches `project_id`, so no trigger list changes.) If it should be allowed, add two
sentences to `00613`'s banner naming **both** directions and the owner-side actor, plus two suite
cases pinning the measured outcomes (`0` and `15000 / studio_member`), so the behaviour is asserted
rather than incidental. Record the ruling id either way; fold round 1's W4-R1-05 into it.
