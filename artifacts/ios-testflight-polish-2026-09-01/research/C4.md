## C4-01 — Today resolves an unknown engagement tier to `.discovering`, so a failed Studio read shows a paying client the brand-new-user home (U45 half-done)
**area** today-home · **severity** major · **testerVisible** yes · **confidence** 0.9 · **effort** M

**where** `Features/Home/Views/DailyRoomView.swift:207-215`; contract at `Core/State/EngagementTier.swift:128-136`; unread signal at `Services/Badges/BadgeCountService.swift:125-129`.

**evidence**
```swift
// DailyRoomView.swift:207
private var tier: EngagementTier {
    switch EngagementTier.currentState {
    case .known(let tier): return tier
    case .unknown: return .discovering        // :213
    }
}
```
`EngagementTier.swift:128-132` says the opposite in so many words: *"`.unknown` is not a tier — it's the
honest answer while the services that derive one are still in flight **or have failed**. The home renders
a skeleton (or a retry) for it, **never the discovering-tier pitch**."*
`BadgeCountService.lastRefreshFailed` (`:129`) was added for exactly this — *"which the home needs to
decide between a skeleton and a retry (U45)"* — and `grep -rn lastRefreshFailed` returns **no reader
outside `OrdersService`**. `resolveState` (`EngagementTier.swift:100-101`) only returns `.known` when
both services loaded, so one failed `BadgeCountService.refresh()` pins the home at `.unknown` for the
whole session.

**why it matters** On a flaky first-launch network an activeProject client opens Today and sees the
composition for someone who has never used Patina: no Record, no designer seat
(`TodayExperience.swift:277-280` gates it on `tier >= .engaged`), and the `startWithARoom` block reading
**"Start with a room"** (`Features/Home/Views/YourHouseRail.swift:317`). The app tells a client with a
live project and an unpaid invoice that they have nothing. There is no retry and no "we couldn't reach
your studio" anywhere on the screen.

**fix** Give `.unknown` its own composition: hold the last snapshot, draw a placeholder Record, and when
`BadgeCountService.lastRefreshFailed` is true draw the `StudioHubView.errorState` line + Try again
(`Features/Profile/Views/StudioHubView.swift:92-113` is already the right component).

## C4-02 — No app-wide connectivity awareness; only the scan lane knows the network is gone
**area** performance-resilience · **severity** major · **testerVisible** yes · **confidence** 0.95 · **effort** M

**where** `Services/Sync/ScanSyncQueue.swift:25,78` (the app's only `import Network` / `NWPathMonitor`); exported as `Services/Sync/RoomScanSyncService.swift:42`; two consumers only — `Features/DesignServices/DesignRequestFlowView+Steps.swift:112` and `Features/Rooms/Views/YourSpacesView.swift:240`.

**evidence** `grep -rn "NWPathMonitor|import Network" --include='*.swift'` hits `ScanSyncQueue.swift`

On the `applinks:client.patina.cloud/piece/*` path the view is constructed with `product == nil` and a
`productId`; `isLoading` is `false` until `.task` (`:123`) calls `loadProduct`. `.task` runs after the
first body evaluation, so the first evaluated branch is `errorView` — an exclamation triangle and
"Couldn't load this piece" with a back chevron.

**fix** Initialise `isLoading = true` when a `productId` is supplied, or hoist the branch to
`if productId != nil && product == nil { loadingView }`.

## C4-21 — Sign Out offline appears to work and doesn't
**area** settings-account · **severity** minor · **testerVisible** yes · **confidence** 0.55 (depends on supabase-swift's local-session removal on a transport throw) · **effort** S

# What is GOOD (calibration)

- **The Studio money lane is the model for the rest of the app.** Invoices, Proposals, Decisions,
  Documents, Budget, Orders and Threads all use the identical
  `PatinaLoadingState` → `PatinaErrorState(+retry)` → `PatinaEmptyState(+CTA)` ladder, with pull-to-refresh
  and empty copy that names the surface and offers the one CTA that unblocks it
  (`InvoiceListView.swift:55-124` is the reference implementation).
- **`Features/Money/MoneyFailureCopy.swift` is exemplary** — a single place where a money failure becomes
  words, written after a Stripe key literally printed on an invoice screen, deliberately pure so
  `errorDescription` can't recurse, and it refuses to guess a payment method. `OrderFailureCopy.swift:42`
  even logs the detail with `(never shown)` in the message.
- **`OrderDetailView.swift:39-58` is the only screen that gets the three-way distinction right**:
  loading vs "we couldn't reach your orders" vs "we couldn't find that order". That is the pattern the
  rest of the app should copy.
- **`StudioHubView.swift:20-113`** — guest state, loading state, partial-load notice, and a total-failure
  error with a `wifi.exclamationmark` and a retry. The only surface outside the scan lane that speaks
  about connectivity.
- **`Core/State/SessionScope.swift`** — eleven singletons reset on the account boundary, with a source-pin
  test that fails on any new `static let shared` holding account data. Sign-in switch does not leak stale
  data into the new account's screens.
- **`BadgeCountService.apply()` (`:233-274`) keeps a stale floor rather than flickering to zero** on a
  partial failure, and `DesignRequestStatusService.performRefresh` (`:875-890`) hydrates from a local
  receipt so a design request survives an offline launch.
- **Alert discipline is excellent.** 11 `.alert` sites total, 9 destructive confirmations, exactly one
  error alert. No alert fatigue anywhere.
- **`DesignRequestFlowView+Steps.swift:112-153`** — a real offline card and a button that changes from
  "Send request" to "Save request". The best offline design in the app; it just exists on one screen.
- `Features/Purchase/BuyabilityGate.swift:90-119` — every refusal has its own honest sentence and a
  separate analytics code, so no server word reaches the screen.

# What I could NOT verify (and why)

- **Nothing is sim- or device-verified.** This lane is a static read; the first-frame flash in C4-20, the
  offline sign-out in C4-21, and the exact GoTrue strings in C4-07/C4-22 all need a walk to pin down.
- **Which raw strings actually appear.** I traced the interpolation sites and the renderers, but the exact
  text depends on supabase-swift 2.40's `AuthError`/`StorageError`/`PostgrestError` `errorDescription`
  implementations, which I read from call-site evidence, not from the SPM checkout.
- **Whether `supabase.auth.signOut()` removes the local session on a transport throw** (C4-21) — that
  decides whether the finding is real or cosmetic; it needs the SDK source or an Airplane-Mode walk.
- **Whether Strata has published `editorial_stories` rows.** If it does not, Today simply never composes
  a `.story` block (`TodayExperience.swift:291`); that is honest but means a prod tester never sees the
  editorial card. Prod data is lane P's.
- **The widget's own loading/empty/error states** — `PatinaWidget` is outside the `Features/**` +
  `Core/Network` + `Services/**` scope I was given.
- **Realtime reconnection behaviour** (`Features/Messaging/Services/MessagingRealtimeService.swift`) —
  whether a dropped socket ever recovers, and whether the tester is told. Needs a live walk.
