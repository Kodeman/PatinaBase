## What is GOOD (calibration)

- **The money rail's failure copy is genuinely world-class.**
  `Features/Purchase/OrderFailureCopy.swift` and `MoneyFailureCopy` map every server code onto a
  sentence, log the thrown error and never interpolate it — the file's header names the exact defect
  it exists to prevent ("the invoice rail printed Stripe's own `Invalid API Key provided: sk_test_…`
  to a homeowner paying $4,250"). `.paymentProcessing` even refuses to say "Nothing has been
  charged" because that would be false in the window it fires in. This is the pattern C5-03 and
  C5-11 should be held to.
- **The Studio empty states are one consistent voice.** Eight surfaces
  (`BudgetView:76`, `DecisionListView:131`, `ProposalListView:99`, `InvoiceListView:104`,
  `ProjectListView:207`, `NotificationFeedView:116`, `DocumentListView:81`, `ThreadListView:186`)
  all follow "Nothing X yet" + "…lands here." + one CTA, and the CTA correctly switches to "Track
  your request" for a client who already filed one.
- **The camera-trust copy is honest and specific** — `CameraPermissionService.swift:19-23`:
  "Your scan—including room geometry and reference photos—is saved on this iPhone first… Finishing a
  scan does not upload it." Exactly the brand's plain-spoken register.
- **The ellipsis character is right almost everywhere** — ~28 sites use `…`; the only `...` in live
  copy is in a dead enum.
- **VoiceOver labels are largely thoughtful and specific** — "Remove one \(title.lowercased())"
  (`ScanFallbackEntryView:233`), "Your note about \(pieceName)" (`SavedNoteSheet:44`),
  "Studio summary: \(hint)" (`StudioHubView:67`), and `RecommendationsView:334-340` deliberately

- **`SavedRowMeta.swift:17-26` writes down the locale rule** and follows it — the codebase knows the
  right answer even where four other formatters don't (C5-25).
- **No internal jargon leaks.** A whole-inventory grep for tier names, flag names, `SP-`/`PT-`/`R##`
  ruling ids, "PostHog", "Supabase", "Strata" and personal names found zero hits in user-visible

  "your designer" before a name reaches copy — the right shape for the guard C5-16 is missing.

## What I could NOT verify (and why)

- **Nothing is sim- or device-verified.** This lane is static by assignment. I did not render a
  single screen, so claims about how copy *wraps* at Dynamic Type sizes, whether a headline truncates,
  or whether an error banner is legible against the red are out of scope here.
- **Which of these strings a real tester's data actually reaches.** Tier-gated Studio copy
  (proposals, decisions, invoices, orders) only draws for a client with an `activeProject`;
  `tester@patina.cloud` may resolve to `.discovering`, in which case only the empty states show.
- **Whether `products.brand` is populated in Strata**, which decides how often C5-16's
  "UNKNOWN MAKER" actually appears. I did not query production tables.
- **Whether GoTrue's exact error strings are what I expect** for C5-03. I verified the *mechanism*
  (raw `localizedDescription` reaching a `Text`), not the specific sentences, which depend on the
  Strata Auth version and settings.
- **The Sanity `helpArticle` / `coachmark` reads used the public CDN with no token.** Memory notes
  that dotted-`_id` documents in this dataset are auth-only; if authenticated-only iOS help
  documents exist, C5-02's "zero articles" would be wrong. The three coachmark docs C5-01 rests on
  came back publicly, which is what the app itself reads, so C5-01 is unaffected.
- **The merged `Info.plist` I read is a Debug simulator build** (2026-08-28). The pbxproj carries
  identical `INFOPLIST_KEY_*` values in the Release configuration (`:731-735` vs `:683-687`), so the
  precedence result carries, but I did not archive a Release build to confirm byte-for-byte.
- **PatinaUITests / PatinaTests string assertions** — I did not check whether any of the copy fixes
  above would break a pinned test string. `FirstLaunchTourTests` is explicitly documented as pinning
  anchor raw values (`FirstLaunchTour.swift:88-104`), so the fix lane should expect test churn.
