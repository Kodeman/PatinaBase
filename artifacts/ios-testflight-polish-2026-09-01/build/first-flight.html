The verdict

The Patina iOS app is a well-made piece of software that has never been shipped, and every one of its problems follows from that: it does not compile in Release, so no archive has ever been produced and everything downstream of an archive is unproven.

Production is still an empty room with three live data exposures on it, the first screen offers a sign-in provider that cannot succeed, and at the tester’s own text size the app’s e-signature sheet puts Approve and Cancel off the bottom of the screen — so round one is not a design problem, it is eight days of unblocking, one archive, and a device pass.

Eight claims have to be true before a build goes to a client. Each is proved at its own level, and none of them is proved today.

  • G1 It archives and uploads. ios-gate.sh archive green on Kody’s machine, the widget appex inside PlugIns/, aps-environment: production and no get-task-allow, and ASC reporting processingState VALID.
  • G2 Production carries the contract the binary calls. Every object the app reads re-probed object by object — not read off the migration ledger, which is how the audit’s own picture went stale.
  • G3 All three exposures are closed, and The Document still works. profiles and notification_preferences return 401 to the anon key compiled into the binary; app.patina.cloud/api/catalog/vendors no longer answers an unauthenticated curl with thirteen trade columns; and the designer portal’s vendors catalogue, comms picker, people directory and roster avatars still render after 00555.
  • G4 The first screen and the first sign-in cannot fail for a real client. No disabled provider on screen, no raw server string on the root, no inescapable guest flow, and a demo credential that actually signs in.
  • G5a The daily Studio surfaces do not lie. Today, the decisions, the designer seat and the Record each have loading, empty and error states that tell the truth, and pull-to-refresh.
  • G5b The surfaces nobody walked have been walked. Proposal signing, decision detail, message send, documents, projects and orders carry 8 findings across all 629 because the audit ran out of time there. “We did not look” is not “it works”: L0.7 walks them and Fable tiers whatever comes out.
  • G6 The marketplace shows real pieces or an honest “still curating” state. Never a grid of grey blocks. One published catalogue product exists today — a $20 Smoke Test Ceramic Lamp with no image.
  • G7 Nothing crash-loops on build 2. A ModelContainer failure is recoverable rather than a fatalError, there is a SchemaMigrationPlan, and BoardModel is in the schema it is fetched from.
  • G8 A device pass has closed every device-only claim. Eighteen rows on the iPhone 17 Pro Max, each passed at device level or explicitly blocked on a named decision — never quietly rounded up.

The program

Four waves and one release round, each wave run as a single Workflow on the pattern the Daily Return established: a steward bootstraps one worktree and one simulator clone per lane, every lane owns a disjoint file set and writes its task list before its code, reviews happen in a separate context, and the steward integrates. W0 is mostly not a code wave — five of its eight lanes are Kody’s hands on a dashboard or a production connection.

The release runbook

Cut from the integration branch after W1 is merged to main, so the archive comes from a main checkout. Version at cut: MARKETING_VERSION 1.0, CURRENT_PROJECT_VERSION 3 — App Store Connect already holds build 2 from 2026-05-12 — identical on both targets or the widget trips ITMS-90473. The archive, the export, the upload and the device pass are Kody’s machine and Kody’s signing identity; an agent runs the read-only listings afterwards. Never a placeholder in a command.

  1. Pre-flight Read-only. Confirm the integrated main tip, the version file, that 00555 landed, and that the build number is strictly greater than every number builds list returns.
  2. Archive The first Kody-only gate, and W1 does not wait on it: it needs an authenticated Xcode account, network round trips to ASC and a keychain that can prompt.
  3. Export App Store Connect method, automatic signing. Read the entitlements out of the exported .app: aps-environment: production, no get-task-allow, and a privacy manifest inside both the app and the appex.
  4. Upload and processing Wait for a new row at version 3 with processingState VALID, minOsVersion 26.0 and usesNonExemptEncryption false.
  5. What to Test, and the internal group Select by build id, never by eyeballing a list. Internal group only: Kody and Leah.
  6. The device pass Installed from TestFlight, not from Xcode — the point is to test the artifact Apple processed.
  7. Beta App Review, then the external group The MiddleWest Client group stays empty until the review passes. Leah’s clients are invited only after the device pass is clean.

The slip rule

The vision’s stop rule is “launching to an empty room — slip rather than demo something broken.” Build 1 does not go to Leah’s clients if, on the morning of the invite:

  • there is no processingState VALID build;
  • any exposure probe still answers 200 to an unauthenticated caller;
  • the designer portal has regressed on any of the four surfaces 00555 touches — The Document takes precedence over the invite;
  • the coverage walk has not run, or produced a blocker that is neither fixed nor named in What to Test;
  • the marketplace shows neither real pieces nor the honest “still curating” state, or a decision cannot be approved at the tester’s own text size.

Slipping is a day. An invited client who opens an empty room is a relationship, and there is no second first impression to spend.

What is already world-class

Nothing on this list may be “improved” by a lane without an explicit ruling. These are the standard the rest of the app is being brought up to.

  • The payment-failure state. “We couldn’t start this payment. Nothing has been charged.” — the model for every error sentence the copy lane writes.
  • The push-permission primer. Asks after the value is visible, in the app’s own words.
  • The Studio money lane. A loading → error → empty ladder with pull-to-refresh, and the invoice detail: three honest states where the rest of the app has one.
  • The typographic system. Playfair headlines, Inter body, DM Mono labels, applied with intent.
  • Reduce Motion in the Companion. Honoured where it matters most.
  • Session survival through a backend outage. The session holds; only the screens lie about the data.
  • The app icon. Icon Composer source with light, dark and tinted renditions and the layered groups intact — the part most apps get wrong.
  • AASA and the deep-link handler match exactly, singular aliases included, live on client.patina.cloud.
  • The phase machine and SessionScope. One reset on the auth seam, 72 shared holders enumerated and pinned.
  • APNs host chosen per token from a recorded environment rather than #if DEBUG — a trap consciously avoided.
  • Defensive product decoding. One bad row is dropped instead of the array, and the category vocabulary drift is absorbed.
  • Withholding unresolved makers. Refusing to print “Unknown Maker” on a provenance marketplace is the right call; it just has nothing left to show today.
  • The test-login edge function. Fail-closed on missing config, an identical 403 on every failure path, rate limits checked before any write, constant-time compare.
  • Account deletion, client-side. Own JWT only, no id in the body, the local store wiped, one human sentence on failure.
  • The Release build settings. dSYMs, stripped, validated, whole-module, dead-code stripping on — correct for TestFlight before anyone tried.
  • The three design-system lint rules have zero hits. Those codemod sweeps genuinely landed; do not regress them.
