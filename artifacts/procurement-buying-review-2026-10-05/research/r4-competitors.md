# R4 — Competitive teardown: how studios buy

Role: competitive researcher. Method: WebSearch/WebFetch only, no device installs, no accounts created. All access dates are **2026-10-05** unless noted. Every row below carries a confidence tag: **[H]** = corroborated by 2+ independent sources or the vendor's own help docs (not just marketing copy); **[M]** = single vendor marketing page or one third-party review; **[L]** = aggregator/listicle, reseller-authored comparison, or a claim I could not corroborate — treat as a lead, not a fact.

Competitor-authored comparisons (DesignFiles on Gather/Programa, Studio Designer on Houzz Pro, Mortar on Houzz Pro fees, etc.) are flagged inline — they're evidence of positioning, not neutral fact.

**Scope discipline per Kody's ruling:** this memo describes what *other companies'* software does. It does not rule on Patina's vision open items. Wherever a pattern below touches margin, markup disclosure, or pricing mechanics, it is marked **RULING NEEDED (V1)** or **RULING NEEDED (R1–R11, see artifacts/pricing-mechanics-2026-09-05)** and left there.

## 2. Patterns worth borrowing (ranked by fit to Patina's actual gaps, per the seed briefs)

For each, the **feature test** (surface / studio moment / stream / promise) per VISION.md, run but never resolved where it touches an open ruling.

1. **Vendor-record defaults cascade onto every PO** — terms, ship-via, account #, attention, FOB, and *address* all live on the vendor record and auto-fill [H] ([help.studiodesigner.com](https://help.studiodesigner.com/s/article/Address-Codes-Settings)). Patina's ship-to is currently hardcoded to "Middlewest Studio · Madison WI" (`step-review.tsx:31` per the seed brief) — this is the most direct, lowest-risk borrow in the set.
   - Feature test: surface = Document/Order Assistant; studio moment = the instant a studio places its first PO for a non-Middlewest client/studio; stream = neither directly, it's plumbing; promise = removes a thing the studio would otherwise have to notice and fix by hand. **Clears the test as infrastructure, not a feature pitch.**

2. **Explicit, dated vendor-acknowledgment lifecycle** (ack date → est. ship → shipped → received, plus a lead-time note) surfaced on *every* order touchpoint, not just one preview panel [H] ([help.studiodesigner.com Expediting & Tracking](https://help.studiodesigner.com/s/article/Expediting-Tracking)). The seed brief notes `LogAckInline` today only exists inside the Ledger resend preview, not in the line unfold — this pattern would close that gap structurally rather than by adding a second copy of the same control.
   - Feature test: surface = The Document (line unfold is upstream of the Ledger); studio moment = chasing a vendor who's gone quiet; stream = none directly; promise = the studio stops needing a second system (email/spreadsheet) to know where an order stands — supports "the studio won't notice Patina."

3. **Grouped/bundled orderable unit spanning multiple underlying components**, approvable as a whole or by part (Mydoma's Grouped Products) [H]. This is the closest existing-market analogue to Patina's workroom/COM gap, though note from §1: even Mydoma's own documented example has the *workroom* supplying the fabric — it does not show the harder case (fabric vendor ≠ workroom) that Patina actually needs modeled.
   - Feature test: surface = Document, FF&E line; studio moment = specifying a custom drapery/upholstery piece; stream = margin on furniture sold (if fabric is marked up) — **touches V1, RULING NEEDED** on whether COM fabric cost flows through the same trade-discount/studio-markup mechanic as a catalog good, or is treated as a pass-through reimbursable. Do not resolve here.

4. **RFQ-before-PO as a first-class, loggable step** (Studio Designer's RFQ-to-chosen-vendor flow; Fohlio's Quote Requests with bulk compare and Excel export) [M]/[M]. Patina's Order Assistant currently treats coverage as a soft "Proceed anyway" gate with no quote-comparison step at all per the seed brief.
   - Feature test: surface = Order Assistant; studio moment = sourcing an antique/one-off or a workroom quote where price isn't fixed; stream = neither; promise = clears if it stays a record-keeping aid, fails if it becomes a second marketplace UI competing with the maker lane.

5. **Client-facing order tracker that is scoped to the project it opened from**, with status badges (paid/shipped/delivered/delayed) [M] (DesignFiles, Houzz Pro Selections Tracker). Directly answers the seed brief's "context loss" finding: Ledger starts unfiltered and Week/Receiving ignore the passed `projectId`.
   - Feature test: surface = Document (client-visible, not Desk); studio moment = a homeowner asking "where's my sofa"; stream = none; promise = **this is the promise itself** — "the homeowner is engaged daily on one agreed direction" — but must not become a second surface competing with the Document; it should render *inside* the Document, not spin up a new app screen.

6. **Trust-accounting separation of vendor-deposit ledger from client-invoice revenue recognition** (Design Manager's named reports: "Open Vendor Deposit Tracking," "Shipping/Receiving/Delivery Reports"; Studio Designer's "client deposits in, vendor deposits out, balances on receipt") [L]/[L] — both claims are vendor-site language I could not verify on a single authoritative page, but the *shape* of the pattern (two ledgers, reconciled, not merged) independently matches AGENTS.md's own rule: "Internal payable-state tables are the source of truth: reconcile Stripe toward them, never the reverse." This is a case where the market convention validates Patina's existing architecture decision rather than suggesting a new one. The seed brief notes `useLogPaymentPaid` has zero callers today — this is the gap the pattern would fill.
   - Feature test: surface = Orders book (Desk); studio moment = paying a 50% vendor deposit before the client's invoice is even due; stream = margin on furniture, **touches V1 at the point markup is "recognized" — RULING NEEDED**, do not resolve; promise = doesn't touch the client-facing promise at all, pure back-office plumbing.

7. **One-click multi-brand sample ordering in a single shipped box** (Material Bank) [H] — not a procurement pattern Patina needs to replicate wholesale (building a logistics network is out of scope), but the *UX shape* — ask for N samples across M vendors, get one tracked shipment — is worth studying for Patina's own samples/memos gap, which the seed brief confirms has **zero** table/model today.
   - Feature test: surface = Document/Library; studio moment = narrowing a fabric choice before client sign-off; stream = none (samples are typically free/trade); promise = clears easily — it's a small, bounded convenience, not an engagement hook.

8. **Per-line vendor-instruction notes field**, explicitly positioned for custom/COM specs rather than a generic comments box [L] (attribution to Studio Designer vs. Mydoma unresolved in my search, see table). The *idea* — a field that exists specifically so "as discussed" never ends up on a PO — is sound regardless of which vendor actually ships it, and lines up with Procurist's procurement-best-practice guidance that vague PO specs are the most common custom-order mistake [M] ([procurist.io](https://procurist.io/blog/purchase-order-best-practices), accessed 2026-10-05).
   - Feature test: surface = Document, line unfold; studio moment = sending a COM cutting-ticket-adjacent PO; stream = none; promise = clears — reduces disputes, doesn't add engagement surface.

9. **Timestamped, evidentiary interaction log** on the client side (view/approve/comment with timestamps) kept separate from any push-notification/engagement mechanism (Planify) [L]. The record-keeping half of this is worth borrowing; the notification half is explicitly flagged as a pattern to avoid in §3 below — they are two different features wearing one name in most vendor copy, and Patina should only take the first.
   - Feature test: surface = Document; studio moment = a dispute over "who approved this line"; stream = none; promise = clears only if it stays a quiet audit trail, not a "come back and look" nudge.

10. **Webhook/real-time sync out to accounting** rather than a bespoke second integration per event (Fohlio's 2026 webhook release) [M]. Useful less as a feature to copy than as validation that the market is moving toward "designer tools emit events, accounting systems subscribe" instead of designer tools re-implementing accounting — consistent with Patina keeping Stripe/QuickBooks-adjacent concerns out of the Document.
    - Feature test: infrastructure, not customer-facing; doesn't need the full test.

11. **A single vetted trade marketplace with concierge logistics and commission-from-manufacturer economics** (DesignerInc) [M] — the closest real-world analogue to Patina's "Patina-grade maker (marketplace) ordering" lane. Worth studying structurally (designer-free, manufacturer-pays, vetting gate, concierge for quotes/damage) even though DesignerInc's own founder has said commission relationships affect search ranking (§3.4) — that part is the trap, not the model.
    - Feature test: surface = marketplace (ranked third, explicitly below Document and iOS app per VISION.md); studio moment = sourcing a piece with no existing studio relationship; stream = margin on furniture sold through designer-led projects — **this entire pattern sits on top of V1 and R1–R11. RULING NEEDED before any of it is built**, specifically: is Patina's cut a manufacturer-paid commission (DesignerInc's model) or a trade-discount-vs-studio-markup split (Patina's own framing)? Flagged, not resolved, per instructions.

12. **Grouped line-item approval UX where a client can approve the whole bundle or drill into parts** (Mydoma) [H] generalizes well beyond COM — it's a reasonable model for any multi-component line (e.g., a configured product with COM/COL options, which Patina already models per `00413_configuration_com_and_decision_selection.sql`).
    - Feature test: surface = Document; studio moment = client reviewing a configured piece; stream = none; promise = clears if the drill-down stays optional and doesn't add a decision the client didn't need to make.

## 3. Patterns to avoid

1. **Automatic "client acted on this selection" push notifications designed to prompt a designer check-in** (Houzz Pro's Selections Board) [M]. This is textbook engagement-bait: it manufactures urgency on the *studio* surface, which VISION.md explicitly rules out ("Never optimize the studio surface for engagement"). The record-keeping half (§2.9) is fine; the push-notification half is not.

2. **Fee schedules disclosed only inside an image file, with per-transaction minimums, capped-then-uncapped ACH fees, and surcharges for instant payout** — a third-party comparison site's characterization of Houzz Pro, explicitly flagged there as "among the most opaque in the category" [L] ([Mortar comparison](https://mortar.design/comparison/best-interior-design-project-management-software), accessed 2026-10-05 — Mortar sells a competing product, treat the specific numbers skeptically, but the *shape* of the complaint — fees not on one page — is corroborated by Capterra reviewer complaints about "confusing charges" [M] ([capterra.com](https://www.capterra.com/p/199689/Houzz-Pro/reviews/), accessed 2026-10-05)). Directly contradicts Patina's "pricing on one public page" promise — worth naming as the anti-pattern to design against, not just avoid incidentally.

3. **Long mandatory cancellation notice windows and a narrow post-cancellation data-export grace period** — a four-to-five-year-old guide describes Houzz Pro's (then-Ivy) service agreement requiring 30 days' notice before renewal and retaining customer data only 90 days post-cancellation [L] ([buildbook.co](https://buildbook.co/blog/how-to-cancel-your-houzz-pro-account), accessed 2026-10-05 — dated source, terms may have changed; a more recent 2025 review says Houzz Pro's cancellation process is now clearer [L] ([machow2.com](https://machow2.com/houzz-pro-review/), accessed 2026-10-05)). Independently, two consumer design apps (Planner 5D, Homestyler) drew Trustpilot complaints about trials that auto-convert to paid with no warning and subscriptions that are "intentionally difficult" to cancel [M] ([Trustpilot via aggregated reviews](https://ca.trustpilot.com/review/homestyler.com), accessed 2026-10-05). Direct violation territory for "no lock-in."

4. **Commission-from-manufacturer economics openly admitted to bias "neutral" search ranking** — DesignerInc's own founder has stated that manufacturers paying commission are promoted over others in search results [M] ([search-synthesized from company背景, not independently re-verified on a primary-source quote](https://www.designerinc.com/)) [L — could not trace to an exact quote/interview, treat as a lead]. If true even approximately, this is the opposite of Designer-Taught Intelligence: a studio-facing recommendation system should never be shaped by who paid for placement, since that silently breaks the promise that Patina surfaces "the right items... at the right place and time" for the *studio's* judgment, not the vendor's spend. This is the central trap inside pattern #11 above — flagging, not resolving, since it sits on V1.

5. **Letting ordering happen entirely outside the platform once client approval is recorded** — an accounting-services blog's critique of Houzz Pro: selections get approved in-app, but vendor quotes arrive by email, get approved in-app, and invoices land in accounting "with nothing linking them together" [L] ([logistis.design](https://logistis.design/blog/how-top-interior-designers-use-houzz-pro-software-to-run-profitable-projects/), accessed 2026-10-05 — single source, framed as a sales pitch for a bookkeeping service, so treat cautiously). Useful mainly as a cautionary contrast: it's the fragmentation Patina's single-Document model is explicitly trying to avoid, so this is a pattern to name as what *not* to become, not a borrow.

6. **Per-seat pricing that taxes a studio for adding its first additional hands** (Studio Designer charges the full plan price per seat with no apparent discount tier; Houzz Pro adds a flat per-seat fee above the included seat) [M]/[M] ([designfiles.co comparison](https://blog.designfiles.co/houzz-pro-vs-studio-designer/), accessed 2026-10-05 — rival-authored, but the seat-pricing structure itself is corroborated by each vendor's own pricing pages). This sits awkwardly against Patina's stated customer definition — "a growing design studio **at the moment it adds its first hands**" — a tool that makes that exact moment more expensive per head works against the moment Patina is designed around. **RULING NEEDED (R1–R11, pricing mechanics)** — flagging the tension, not proposing Patina's own seat pricing here.

## 4. Where nobody does it well (open ground)

1. **COM as a two-vendor chain (fabric house ≠ workroom), with leftover-yardage disposition captured structurally rather than as a manually-typed contract clause.** Every source on COM handling — including Mydoma's own documented Grouped Products example — resolves to "the workroom supplies the fabric," or punts to blog advice telling designers to write a leftover-fabric clause into their own PO/work-order templates by hand [M] ([interiordesigncommunity.com](https://interiordesigncommunity.com/leftover-com-fabric-ownership/), accessed 2026-10-05). No platform reviewed links a fabric PO to a workroom work order as one traceable chain. This is precisely the gap the intake seed brief identifies for Patina ("Workroom: rolodex label only, no work order and no COM fabric shipment linking fabric to a workroom") — genuinely open ground, not a catch-up item.

2. **Phone-based receiving with damage photos and a claims workflow, inside the design-business platform itself.** Confirmed absent across Studio Designer (mobile = time-tracking only [H]), Programa (no app found [M]), Houzz Pro (fullest app of the set, but no source shows receiving/damage photos [M]), DesignFiles and Mydoma (not confirmed either way). That function lives entirely in third-party receiving warehouses — Ocotillo Services' "TOC" portal, Hilldrup, Expo Movers all independently describe item-level photo inspection and damage documentation as *their* job, not the design-software's [H] (three independent moving/receiving-company sources agree: [ocotilloservices.com](https://ocotilloservices.com/articles/the-essential-role-of-an-interior-design-receiving-warehouse/), [hilldrup.com](https://www.hilldrup.com/logistics-solutions/interior-design-receiving-and-delivery/), [expomovers.com](https://expomovers.com/receiving-and-delivering-furniture-for-interior-design-needs/), all accessed 2026-10-05) — or in a generic inventory app (Sortly) not built for design workflows at all. Patina's own schema (receiving inspections, damage claims, a "receiver" role per the intake brief) is structurally ahead of the market here; the gap is that desktop still "defers to mobile" and iOS photos aren't openable from the web per the buying-flow brief. This is a real opening, but note the Patina-grade caution: building it well is an infrastructure win for the studio moment of "did it arrive intact," not a feature to chase for its own sake — and it must not become the kind of photo-tagging-as-content-loop pattern that drifts toward engagement design.

3. **Antiques, estate pieces, and other genuine one-offs modeled as something other than a forced permanent vendor record.** Every platform reviewed requires a vendor record to issue a PO; none distinguish a one-time flea-market/estate seller from a repeat trade account with terms. Patina's own gap (a flea-market piece needs a made-up vendor record, per the intake brief) is the market's gap too — nobody has solved "buy one thing from someone who isn't a vendor."

4. **Reimbursables, CFA, and retail/card purchases as first-class procurement lines with purchaser/paid-by tracked against reconciliation.** This work is universally pushed one layer down into QuickBooks/Xero via integration, several steps removed from the FF&E schedule itself. No platform reviewed shows "who paid, on what card, reimbursable yes/no" as a field on the schedule line the way price, vendor, and status are. The seed brief confirms Patina has zero hits on CFA and reimbursables today — this is unclaimed territory, not a catch-up.

5. **A client-trust deposit/balance ledger that is both structurally sound (two reconciled ledgers, per Design Manager/Studio Designer's own positioning) and radically unobtrusive on the studio side.** Every vendor that claims strong trust accounting (Design Manager, Studio Designer) is also the vendor users describe as complex and overwhelming — "even a CFO couldn't figure out what was going on" per one DesignFiles-sourced quote [L] (rival-authored, single quote, treat cautiously). Nobody has shown that rigor and the "studio won't notice Patina" promise can coexist. That combination — not the ledger mechanics alone, which the market has solved — is the open ground for Patina specifically.

## 5. Notes on method and gaps in this pass

- No live walkthroughs, no accounts created, no device automation — consistent with the read-only instruction. Everything above is secondary-source synthesis; several claims are tagged **[L]** specifically because WebSearch's own synthesis (not a primary document) is the only trail I could follow, and a few (Studio Designer workroom/work-order split, DesignerInc's ranking-bias claim) have ambiguous or unconfirmed sourcing that I've flagged rather than smoothed over.
- "Sidemark-style" tools: I found no software product literally named Sidemark that does procurement — mysidemark.com is a GoHighLevel-based marketing/CRM tool unrelated to purchasing [H] ([mysidemark.com](https://mysidemark.com/interior-designer-software-solution), accessed 2026-10-05). "Sidemark" the *procurement concept* (tagging an order with client/project/room so it ships correctly) is universal across every platform reviewed and is already present in Patina's own schema (`purchase_orders` sidemark generator, 00186, per the intake brief) — so Patina is not behind the market here, there's just no dedicated "Sidemark Inc." to benchmark against.
- "Trove-style" tools: same story — no procurement software named Trove; the closest real analogue to a curated trade marketplace is DesignerInc (§1, §2.11, §3.4), with Material Bank/Clippings as the sample/sourcing-adjacent comparison.
- Fohlio's Spec Hub is marketing itself simultaneously as "Now in Beta" and "Coming Soon" on the same page — I could not confirm GA status, and treated every Spec Hub claim as directional, not a shipped-feature fact.
- I did not find any 2025-26 genuinely new entrant beyond Fohlio's relaunch; Gather, Mydoma, DesignFiles, Programa, Studio Designer and Houzz Pro all read as the same incumbent set with incremental 2026 releases, not a changed competitive landscape.
