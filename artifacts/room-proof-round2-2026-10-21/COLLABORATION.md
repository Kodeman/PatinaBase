# Claude Code × Codex — round two

The user asked the two collaborators to implement the relevant feedback they could agree on. Claude Code (Opus alias, CLI 2.1.306) first recorded agreement in AGREED-DESIGN.md and authored the HTML presentation. Codex implemented the connected mockups. A fresh Claude Code session independently reviewed Codex's implementation; Codex reviewed and tested Claude's presentation.

Claude's prototype review found no blocking issue or misstatement of authority, money or release. It affirmed that the left-weighted room and right-hand work retained the approved identity. The following observations were then applied:

| Review finding | Result |
| --- | --- |
| Urgent work was lower in the desk list; four projects had no action. | Eight actions now cover all six projects and sort by due date. Illustrative actions open explicitly labelled overview studies. |
| Time and Orders lacked a selected navigation marker. | Time joins the project row; Books/Menu indicates the active book. |
| The mobile decision action was below the fold. | The selected piece's state and primary design-review action appear before supporting detail. |
| A selected blue pin could look approved. | Selection uses an offset outline. Approved fill and reference-only dashed marks retain their separate meanings. |
| The large deposit figure competed with authority. | The deposit card uses a smaller ledger figure and retains its qualification in both wording modes. |
| Mobile fields were small. | Inputs/selects/textarea text use 16px on mobile; the rate selector uses the full form width. Native iOS behavior remains untested. |
| A reference-only piece lacked a desktop margin label. | The piece state is visible on desktop and mobile. |
| Order summary lacked an owner and stale-draft warning. | The next responsible person and stale saved-draft warning appear at the top of the order. |
| Specimen labels were too quiet. | Labels are stronger, consistently worded; blocking reasons are complete sentences. |
| A first-screen tile was captured before its image loaded. | Eager image loading and decoded-image capture remove that ambiguity. |

The initial critique proposed a linear standing chain and removal of all warnings. Both collaborators instead agreed to independent facts plus a release outcome, preserving consequence wording at actions. No new authority or payment workflow was added.

Codex's presentation review corrected a duplicate comparison ID, ensured side-by-side desktop frames remain equal at 1440px internally, separated founder-note storage from prototype storage, and aligned claims and figure references with the implemented mockup. Notes/export and navigation were then exercised in the assembled presentation.

This is a design review and local prototype, not production verification or user research. The five added project overviews, material plates and future-state gallery remain explicit specimens. Full provider responses are preserved under review/.
