# Room Proof — A working rhythm

A new HTML review presentation and connected mockup round developed with Claude Code, incorporating the feedback agreed by both collaborators. The approved Room Proof direction remains; navigation, context, working density and mobile tasks have been refined.

Open **index.html** for the founder presentation. Open **mockup.html?view=desk** for the working sample. The presentation includes previous/proposed comparisons, a six-scene explorer, three mobile tasks, a state gallery and local founder notes.

## Run locally

Keep this folder beside `room-proof-workflows-2026-10-21`, the prior round. Both are included in the review bundle. From this folder:

```bash
python3 serve.py --port 8080
```

Visit **http://127.0.0.1:8080/room-proof-round2-2026-10-21/index.html**. The server binds to this computer only and serves the parent artifact directory so comparisons can load the earlier round. Assets and fonts are bundled. No CDN, analytics or application API is required.

## What changed

- A compact global masthead, project selector, direct Inbox and contextual project sections including Agreement and Time. The desktop dock and tour strip are removed from the working surface.
- A six-project contact sheet and a due-date-ordered action list. Five additional projects are clearly labelled illustrative overview studies.
- The room, account and order use consistent independent facts for design, purchase authority and money; release is an outcome with named blockers.
- Selected pins use an outline; fill is reserved for an approved edition. Reference-only pieces are identified in the margin.
- Approval preparation puts the issued revision and its included pieces on the left, with the draft request on the right.
- Compact operational headings, readable financial totals, an immediate time-entry shortcut, and a stale-order warning with its responsible person near the top.
- Mobile layouts for the design decision, recording time and receiving an item. Receiving now requires an explicit inspection outcome.

## Working versus illustrative

The original 13 connected workflows remain, plus the project-overview and state-gallery views. Lake Mendota is the interactive project. Oak Street has the separate original receiving example; its overview and the other four additional projects are visual studies, not additional transactional backends.

The state gallery is noninteractive. The first two conditions are reachable in the sample; authorized-but-held and released conditions are clearly labelled **Specimen: not a working state**. No action grants purchasing authority. Approval, money, vendor obligations and order release remain distinct.

All names, amounts and messages are fictional. Everything stays in browser storage. No correspondence is sent, payment processed, order released or production portal changed. The current functionality map and source baseline remain those of the previous round; see **SOURCE-MAP.md** and the link in the presentation.

## Review notes and sample state

The old mockup, new mockup and founder notes have different storage keys. Resetting the sample does not clear founder notes. Notes can be saved locally and downloaded as Markdown. All round-two preview frames share saved sample state: use one editing preview at a time. Unsaved form text is not synchronized.

The compact/full explanation comparison changes supporting wording only. Consequence language at decisions remains. Previous/proposed comparisons run at equal internal desktop sizes; on a phone, both use 390 × 844.
