## Skeptic findings — trust, rulings, risk and cost

**Evidence boundary.** Recommendations below are based on the current vision/rulings and code/docs named; confidence is how directly the evidence supports the conclusion, not a probability that a future model is correct. “Severity” is product harm if ignored. Do not build a general Claude layer before the founder rulings in §2—especially the open studio-review ruling.

### 1. Trust contract (proposed invariant for every model-backed feature)

1. **A human owns every consequential commit and send.** Model output is a candidate, never authority: no external message is sent, purchase order/invoice is issued, or business record committed until an identified person previews/edits and explicitly confirms. This already matches the Agent OS “drafts land `awaiting_review`” rule (`CLAUDE.md:28–35`) and procurement’s deterministic-template, member-click gate (`supabase/migrations/00706_procurement_drafts.sql:7–11`). No numeric confidence threshold can bypass it. **Severity critical; confidence high.**
2. **Mark model-originated content where it lands.** Preserve source/provenance on the exact field or placed item (“via the Engine” is R38’s precedent), distinguish model suggestion from maker/source-of-truth data, and carry source/version metadata through edit and export. Do not silently relabel generated content as designer-authored. R38 explicitly pairs no ask history with a persistent placement mark (`DECISIONS.md:1552–1558`); existing enrichment currently writes allowlisted suggestions into empty capture columns (`00515_capture_enrichment_rpcs.sql:274–292`), so field-level provenance/review remains a real gap. **Severity high; confidence high.**
3. **Asks are ephemeral, not product memory.** Do not store prompt, transcript, or reconstructable conversation; retain only the user’s explicit act and the minimum audit/usage metadata that cannot reproduce the ask. Delete request payloads from error/analytics logs too. R38 says “no thread, no history; the ask itself does not persist”; I30 rejected `companion-message`’s stored `companion_messages` on that basis (`DECISIONS.md:1558,1603–1607`). **Severity high; confidence high.**
4. **Ground claims in inspectable evidence.** Product, price, dimensions, finish and lead time must cite the actual catalog/source document/line/page and its freshness; do not turn a model’s fluent guess into a fact. If unsupported or sources conflict, say “not found / needs checking” and leave the field unset. A citation must substantiate the displayed claim (including units/currency), not merely link to the whole source. **Severity critical; confidence high.**
5. **Show uncertainty as an action cue, never a score.** No confidence percentages, rankings of designers, accuracy meters or red/green quality badges. Use quiet phrases such as “suggested—check source” / “unclear” and identify the field needing confirmation; uncertainty may order an internal review queue only, never commit. FC-R12 rules out auto-apply at any confidence (`field-companion-rulings.md:47,710–730`); vision refuses engagement metrics and dashboards (`VISION.md:48–58,66–75`). **Severity high; confidence high.**
6. **Make every applied change reversible.** Preview the diff, identify the changed destination, retain the prior value, and offer a local undo/restore action; sending is a separate irreversible explicit act. A correction must not silently train/rewrite unrelated records. **Severity high; confidence medium** (recommended safeguard derived from the trust contract; not a cited settled ruling).
7. **Minimize and protect inputs.** Send only the task’s necessary, authorized fields. Never send API keys/secrets, credentials, payment/bank/tax data, unrelated project/client records, private messages/audio, or identifiable homeowner material without the required consent and disclosed purpose. Redact identifiers by default; enforce studio/project authorization server-side before retrieval and before persistence. Homeowners are the studio’s clients, not Patina’s (`VISION.md:27–36`); FC-R11 requires consent and a lawyer’s review before a non-Kody designer records a client (`field-companion-rulings.md:29–33`). **Severity critical; confidence high.**
8. **Stay quiet, fail closed, and retain human control.** No interruption unless designer-invoked (D2: `DECISIONS.md:9–13`); unavailable, timed-out, refused, ungrounded or malformed output means no write/send and a quiet retry/fallback. The paper UI must say it is still working or offer a deterministic route, not force a chat workflow. **Severity high; confidence high.**

### 2. Founder rulings required before build (recommendations)

1. **Agent-composed studio drafts (open ruling): RULE before any model-composed text reaches a studio, even as a draft.** Recommend allow only a named studio reviewer, clear provenance, editable preview, and explicit send; until adopted, continue deterministic SQL templates only. VISION-DECISIONS says studio review remains open (`:419`), and migration 00706 explicitly records that it therefore has no agent composer (`:7–11`). **Critical / high.**
2. **Resolve the three implementation contradictions as a family, not feature-by-feature.** (a) Re-open/align SMS’s ≥0.8 auto-apply path (`sms-inbound/pipeline.ts:17,1825`) with FC-R12’s no-auto-apply rule; (b) change capture enrichment’s silent fill of vendor/SKU etc. (`00515_capture_enrichment_rpcs.sql:250,274–292`) to visibly reviewable suggestions; (c) stop companion history persistence or keep it out of the Engine path (`DECISIONS.md:1607`). FC-R12 explicitly calls for the family to be ruled with FC-R18’s owner (`field-companion-rulings.md:725–730`). Recommend one invariant: model never applies at any confidence; person confirms. **Critical / high.**
3. **Naming: UI uses “Designer-Taught Intelligence”; “the Engine” only in the defined internal/product surfaces; never “AI.”** Follow VISION’s hard ban (`:66–75`) and lexicon’s explicit AI/artificial-intelligence/ML/LLM errors (`marketing/canon/lexicon.json:19–47,95–98`). Resolve briefs’ “engine” ban against R38’s product-copy permission by limiting “Engine” to R38’s approved, context-specific presence; generic campaign/UI copy should use the full canon name, not silently broaden an exception. **High / high.**
4. **Homeowner data consent/disclosure: require explicit studio authority and clear disclosure before any identifiable client data leaves Patina’s boundary; yes, have counsel decide whether and how the studio’s client agreement must mention model processing.** Do not assume a designer’s consent alone binds the homeowner or vendor. Default to de-identified/minimized context; opt out must preserve a usable non-model path. FC-R11 sets a consent baseline for recording and lawyer review for non-Kody designers (`field-companion-rulings.md:29–33,415ff`); extend only through an explicit legal ruling, not an implied consent. **Critical / medium** (legal answer requires counsel).
5. **Teaching corrections / Pledge: do not treat every correction as royalty-bearing teaching until Kody and counsel rule it.** Recommend an explicit, attributable opt-in “contribute this correction” act, defined scope/retention/use, revocation/correction path, and royalty formula before using it to improve shared intelligence; private project corrections remain private by default. Vision says the Pledge is legal-gated and royalties ride on marketplace margin (`VISION.md:38–46,58–62`), not that every edit grants training rights. **High / medium.**
6. **Operational gate: designate one canonical server-side key name and require bounded timeout, spend limits, and per-feature/studio usage accounting before expanding calls.** Current code uses both `ANTHROPIC_API_KEY` (e.g. `project-ffe-document-extract/index.ts:84`) and `CLAUDE_API_KEY` (`_shared/field-parse.ts:489`); the FFE extractor fetch does not pass an abort signal and reads response content but no usage totals (`:86–110`). **High / high.**

### 3. Risk register

- **Prompt injection in vendor PDFs, SMS, scraped product pages, client emails — High severity / high confidence.** Treat all source text as untrusted data, never as instructions; separate system policy from quoted content, strip/disable tool authority for extraction, allowlist tools/fields and destinations, validate outputs against source and schema, cap bytes/tokens, and require human review. An injected PDF instruction to change a vendor payment destination must be inert; no model call gets payment or send tools.
- **Hallucinated prices/dimensions/lead times reaching PO or invoice — Critical / high.** These are commerce facts, not generative fill: only copy from a current maker/catalog source with unit/currency and citation; validate against authoritative rows and totals in ordinary code; unknown/conflicting values block PO/invoice issuance pending user verification. Agent output cannot mutate payable state (Agent OS source-of-truth rule, `CLAUDE.md:31–35`).
- **Cost runaway — High / high.** Hard per-request input/output and wall-clock ceilings; per-studio quotas/alerts and global kill switch; account actual input/output/cache usage, retries and model; deduplicate/idempotency keys; cap file sizes and use batch only for latency-insensitive work. No shared usage logging is an operational gap; FFE extraction’s code currently does not consume returned usage (`project-ffe-document-extract/index.ts:86–110`).
- **Vendor lock-in versus “no lock-in” — High / medium.** Keep project data, prompts, schemas, citations and audit records in Patina-controlled portable formats; provider adapter only at inference edge; export/delete controls, provider-neutral evals, fallback deterministic behavior, and no proprietary provider memory as the canonical record. This follows explicit data-export/no-lock-in promise (`VISION.md:48–54`).
- **Model deprecation/drift — Medium / high.** Pin model ID per feature; maintain representative regression/eval set and versioned prompt/schema; watch retirement notices; test candidate before switch and retain rollback; fail closed rather than auto-switching to a lower-quality model. A feature’s authority remains code+review, not model identity.
- **Latency in paper UI — Medium / high.** Invoke only on designer intent; preserve the paper surface and current task, show a quiet inline working state, bound deadline, cancel/retry, and return to deterministic catalog/search on timeout. Never interrupt by default (D2) and R38 specifies inline paper results and a quiet “thinking” state (`DECISIONS.md:1556`).

### 4. Refused categories (outright)

- **Auto-send client updates or vendor messages:** refused by “every outbound message is a draft a person sends” (`VISION-DECISIONS.md:417`) and Agent OS `awaiting_review` (`CLAUDE.md:33`).
- **Client-facing Patina chatbot / consumer support surface:** consumer-first drift; homeowners are the studio’s clients and Patina does not sell to them (`VISION.md:27–36,66–75`). Any homeowner-facing wording belongs to the studio’s authored/sent relationship.
- **Generated imagery depicting a client’s actual home or proposed design direction:** risks representing an unagreed direction as real; homeowner promise is that designer and homeowner see the same agreed direction (`VISION.md:48–54`). Use only if founder separately rules a controlled concept-rendering workflow with consent, provenance and review; not a default feature.
- **Designer productivity, response-time, taste or “AI accuracy” scores/leaderboards:** “never optimize the studio surface for engagement,” “no dashboards,” and no scores (`VISION.md:48–58,66–75`); teaching is quiet, never gamified (`DECISIONS.md:1566`).
- **Autonomous purchase/invoice amounts or auto-converted spoken measurements:** FC-R12 “nothing auto-applies at any confidence” and FC-R16 says spoken measurements never become measured records (`field-companion-rulings.md:47–49,763–774`).
- **Persistent assistant chat history or a “memory” trained from private project asks:** violates R38’s “no thread, no history; the ask does not persist” (`DECISIONS.md:1558`) and the existing companion-history objection (`:1607`).

### 5. Cost sanity check (illustrative, not forecast)

Using supplied prices, assume ordinary uncached monthly traffic per studio: **100 Sonnet 5.5 assisted asks** at 20k input + 1k output tokens each = 2.0M input × $2/MTok + 0.1M output × $10/MTok = **$5**. Add **500 Haiku 5.5 extractions** at 3k input + 500 output each = 1.5M × $0.10 + 0.25M × $0.50 = **$0.275**. Baseline ≈ **$5.28/studio/month** before retries, infrastructure, image/PDF tokenization, shared prompts, logging and support. A heavier studio at 300 Sonnet asks (40k/2k) plus 2,000 Haiku extractions (5k/500) costs **$30 + $1.50 = $31.50**. A Sonnet-heavy 1,000 asks at 40k/2k alone reaches **$100**. Opus at the supplied $4/$20 rate doubles the Sonnet cost for equal token volumes; batches halve eligible batch work, and cache reads at ~0.1× can lower repeat-prefix input, but initial cache writes/uncached inputs remain. Thus likely manageable at modest usage but not safe to bundle without quotas: the high-volume scenario can eat the working $49 Pro price or substantial share of $149 Studio (VISION-DECISIONS V2 remains open; VISION.md:42,85). Model API cost excludes compute/ops and is not a quote. Recommend usage caps/transparent policy before subscription inclusion; no per-studio bill-back/hidden usage charge without a public pricing ruling. **Confidence medium** (volumes assumed; arithmetic high).
