Method

The family today

Two apps, two audiences, one backend

Not a consumer app and a pro app. The two halves of a designer‑led project — the homeowner's side and the studio's side — sharing a database and almost nothing else. Both are strong. Both leak at the same seam.

Patina cloud.patina.app · iOS 26.0 floor

The homeowner's side

Who. A homeowner who is a designer's client. Guest browsing is first‑class; sign‑in is required only to send a design request. App Store category: shopping.

What. Four hand‑rolled tabs — Today, Spaces, Pieces, Studio — plus a Companion in a fifth non‑tab slot. LiDAR room capture, a style quiz, saved pieces, then approve / sign / pay / track what the studio does.

Scale. 479 app source files, 2,735 test cases, 674 commits in 60 days.

Patina Field cloud.patina.field · iOS 18.0 floor

The studio's side

Who. Invite‑only — sign‑in refuses to create an account, because designers are provisioned through the portal. A workspace is an organisation. There is a fourth door: an unauthenticated guest (a sub, a GC) who arrives on a texted link and sees only the site‑request screens.

What. Two peer realms, camera and work. Turn a showroom object into a structured, located specimen; run a LiDAR site scan onto a project; receive goods; hold a roster; log hours; send site requests.

Scale. 272 source files plus a 114‑file SDK‑free CaptureKit; 79 screen ids; a generated Xcode project.

What is genuinely good

  • Field's offline model is first‑class. Five durable queues, client‑minted UUIDs as idempotency keys, and a store that degrades loudly rather than silently. "The door MUST work offline: never an empty list, never a spinner, never a disabled control."
  • Field's recognition grammar. Every machine‑proposed value carries a provenance chip and is confirmed or corrected by a human — with one hole, on slide 9.
  • Patina's copy discipline — a test‑enforced lexicon, plus sentence‑case, contrast and tap‑target suites — and its permission choreography: a purpose‑built primer before every system prompt, with a real alternative on denial.

Where users stall

  • Field Six built screens are unreachable in a Release build — Settings, Account, sign‑out, workspace switch, the QR approver, the photo‑import fallback. A signed‑in designer has no exit.
  • Field No push, and no local notifications. The app whose user stands on a job site cannot be told anything.
  • Patina The whole studio rail is online‑only. Invoices, decisions, proposals, threads, documents and orders have no local model; offline they are six identical "try that again" cards.
  • Patina Non‑LiDAR users get the worst path — manual room entry, which once shipped pre‑filled dimensions that read as measured fact.

Constraints · read before believing any demo

Five gates that decide what is actually buildable

1. The toolchain gate — the one nobody costed

This machine runs Xcode 26.6 (17F113) and the only installed iOS SDK is 26.5. Attachment, OCRTool and BarcodeReaderTool are iOS 27 SDK symbols and cannot be compiled here today. The repo's iOS CI gates run on macos-15, an image that does not ship Xcode 26, let alone 27.

So any iOS 27 feature's true prerequisite list opens with an Xcode upgrade and a CI runner‑image bump — before a line of product code. Evidence xcodebuild -version, .github/workflows/policy-quality.yml:95,104

2. The device gate

Apple Intelligence needs A17 Pro or newer: iPhone 15 Pro / Pro Max, iPhone Air, iPhone 16 and later. Not all iPhone 15s. It also needs the model downloaded, Apple Intelligence enabled, and a supported language.

Third‑party estimates put the eligible base near 40–55%; Apple publishes no figure. But that number is irrelevant here: there are zero third‑party studios in production. The real population is Leah's crew and her trades — a census question, not a statistic, and nobody has asked it.

3. The sandbox gate

Spotlight semantic‑index retrieval is limited to your own app sandbox. Two apps from the same developer — even sharing an App Group — cannot retrieve each other's indexed entities. Apple stated this directly in the WWDC26 Apple Intelligence Group Lab; Transferable is the sanctioned cross‑app path.

Consequence: "ask across both apps" is not buildable on the index. Cross‑surface retrieval stays server‑side.

4. The context gate

SpotlightSearchTool defaults to a guidance level Apple says "works best with Private Cloud Compute models." Without a focused(_:) guide, Apple warns plainly: "Spotlight search exceeds the context window of the model and can't return results." The on‑device window is roughly 8K and hardware‑dependent — read contextSize at runtime rather than assuming.

5. The schema gate

App Intents schema domains are a fixed list — Audio, Calendar, Camera, Clock, Mail, Maps, Messages, Notes, Phone, Photos, Reminders, and system / in‑app search. There is no domain for furniture, projects or field work.

A custom intent still reaches Shortcuts, Spotlight, the Action Button and Control Center. What it does not get is free Siri phrasing. "Just say it to Siri" for a specimen would be over‑claiming.

Two pieces of good news

Patina qualifies for free PCC today — Small Business Program, under 2M first‑time downloads, plus the entitlement. TestFlight installs do not count.

There is no iOS 27 SDK deadline. Apple's Upcoming Requirements page still mandates only the iOS 26 SDK. Adopting 27 is a choice, not a compliance date — which means gate 1 can be scheduled rather than rushed.

The challenge round

Three things I had wrong

My shortlist was a tag reader, an entry point and a design‑system move. Astra and the red team dismantled two of the three. Each correction below was re‑verified first‑hand before it went in this deck.

1. The Live Activity is not running

I wrote that Field starts a Live Activity that nothing renders. False. Capture/Info.plist contains exactly two keys and NSSupportsLiveActivities is not one, so areActivitiesEnabled is false and the controller returns at its guard. Nothing is requested.

This cuts both ways: the gap is bigger (two missing pieces), and the first fix is much smaller — one generator line, after which you learn on a device whether the payload is even correct.

2. The floor bump was wrong twice

I said the tag reader needs Field's floor raised 18 → 26. Insufficient: the multimodal surface is iOS 27, not 26. Unnecessary: weak linking plus @available reaches a 26/27 API from an 18.0 floor. The device cut buys nothing and strands users.

3. The provenance chip does not persist

My third item promoted Field's provenance grammar to family law. But SmartGuessSheet.accept() — the single "Looks right" tap — rewrites every unchanged value to .manual, defined in the enum as "typed by the designer." The dashed chip is erased on acceptance.

With four eyeball‑checkable classifications that is fine. Route a model‑generated SKU and trade price through it and you have a machine that turns a guess into a designer's typed value in one tap, with no trail.

Exporting that grammar to a second app would have exported the hole with it. Fix accept() first — that is a few lines inside one file, and it is the entire safety argument.

Also flagged, and accepted

Badges are refused by name. The vision document's list of refused UI includes badges and red/green status. ProvenanceBadge is a badge with a three‑colour status palette. It may have earned a local exception inside Field's recognition sheets; promoting it to shared law makes a refused pattern into house rule.

"The Engine is resting" is not a universal failure line. It belongs to one endpoint. An expired session, a denied camera and a failed upload are different failures and deserve truthful, operation‑specific copy. The no‑"AI" rule stays; the single sentence does not generalise.

What survived the challenge

The evidence base held: every count, every file reference, the zero‑adoption table, the terminology collision, the contrast defects, the six unreachable screens, the missing push rail, and the verified Apple capability matrix. What did not hold was my ranking — and both reviewers, independently and from different evidence, pointed at the same replacement.

Opportunity 1 · Shared — the portal first, then Field's camera

The vendor PDF reaches the Document

The problem

A vendor sends a quote or an acknowledgement as a PDF. Somebody at the studio retypes it into the FF&E schedule — maker, SKU, finish, quantity, trade price, lead time — line by line. It is the least designerly hour in the week and it sits on the surface the company ranks first.

Meanwhile project-ffe-document-extract already exists: it authenticates the caller, verifies the uploaded source manifest and hash, runs the extraction, validates the result, and stages the rows through stage_project_ffe_document_extraction. It is registered in config.toml, ACL‑hardened by two migrations, and exercised by two SQL test files.

Across the whole repository, not one portal, app or cron job calls it.verified 23 Sep 2026 — the only non‑Supabase hit is a generated type

The improved experience

She drops the PDF on the project. The schedule shows the extracted rows staged beside the page they came from — each row with the excerpt that produced it, each field editable, nothing committed. She confirms row by row. What she confirms lands in the Document as the one canonical record.

Why this is the strongest item on the list

  • It is the only item on surface #1, the Document — which the company's own strategy calls "Patina for the next 12 months."
  • It touches the margin stream directly: a furniture schedule is where the money is described.
  • No Xcode upgrade, no CI bump, no deployment floor, no hardware gate. It works on every device both apps support today, because the model runs on the server the company already pays for.
  • It keeps the intelligence server‑side, where the company's actual asset lives, instead of forking it along an app boundary.

Smallest useful version

One flag‑gated route in the designer portal that posts a PDF to the deployed function and renders the staged rows for per‑row confirmation. No commit path, no new model, no iOS work.

Effort & dependency

S–M. A route, an upload, a review table. Depends on nothing that is not already deployed. The second step — Field's camera posting a tag photo to the same extractor — is a separate, later decision.

Principal uncertainty

Whether extraction is accurate enough on real vendor paperwork to be worth reviewing rather than retyping. That is exactly what the first experiment measures — slide 17. Deployment, credentials and current ACLs are also assumed, not confirmed.

Success criterion

Field‑level exact‑match against a hand‑keyed gold set: ≥95% on SKU and price, ≥90% on maker. Below that, per‑row confirmation stays mandatory forever — which is the safe default anyway.

Opportunity 2 · Patina Field

The jobsite app cannot be told anything

The problem

Patina Field's user is the person furthest from a desk: on a site, on a roof, in a van, in a showroom. Capture.entitlements declares app‑groups, Sign in with Apple and associated‑domains — and nothing else. A search across the entire Capture tree for aps-environment, UNUserNotificationCenter or registerForRemoteNotifications returns zero.

Not "push is unfinished." The app has no notification capability at all, local or remote. The studio's only channel to that person today is SMS.

The improved experience

A designer changes a spec at 4pm. The installer holding Field sees one line: the Harper dining table spec changed — open it. Tapping it opens that record. That is the whole feature.

Why this ranks second

It is the only item that adds a capability the app cannot do at all, for the user with the least alternative. Everything else on the list makes an existing thing better.

And it is cheap: an entitlement, a UNUserNotificationCenter registration, and a token upload onto the device‑token rail the client app already uses. No new backend.

The discipline this needs

  • Name one real missed instruction first. Not "Field has no push" — one actual assigned request or changed spec that Leah's crew missed this month. If nobody can name one, this drops down the list.
  • Narrow, permissioned, deduplicated. A notification centre or an engagement campaign is a different, worse product.
  • Push is never the source of truth. It links to the record; the in‑app pending‑work view stays authoritative.
  • Nothing external is sent automatically — the house rule that drafts land awaiting_review applies here too.

Smallest useful version

One notification type, for the one missed‑instruction case the studio names. Opt‑in, deep‑linked to the record, deduplicated.

Effort & dependency

S–M. Entitlement, registration, token upload. Hard dependency: the six unreachable screens — a user who cannot reach Settings cannot turn notifications off. Fix that first.

Principal uncertainty

Content, not engineering. What does a studio actually send to someone on a roof? That is a five‑minute conversation with Leah — and it is a conversation the company already owes.

Success criterion

Median time from a designer's change to the field acting on it, against today's SMS baseline. Plus the guard‑rail: opt‑out rate under 10%.

Opportunity 3 · Patina, the client app

The agreed direction stays readable

The problem

The client app's promise is that the homeowner is engaged daily on one agreed direction. But PatinaSchema's nine local models cover rooms, scans, saved items and the style profile — and not one of decisions, proposals, documents, invoices, threads or orders.

Every studio surface is a live fetch. In a basement, on a plane, on hotel wifi, the entire studio half of the app becomes six identical "try that again" cards. The one thing the homeowner is supposed to carry with her is the one thing she cannot open.

The studio's side is built to survive no signal. The homeowner's side is not — and she is the one away from a desk.

The improved experience

She opens the app with no bars. The last thing the designer shared is there — the direction, its revision, the decision being asked of her — marked plainly with when it was last fetched and a route back to the live record. Nothing consequential is approved from cache: tapping Approve revalidates first, and says so if it cannot.

Why this, and not a badge or a chatbot

The vision document is explicit that the client app is the studio's front door, not a consumer product in its own right. That rules out an independent shopping feed or a conversation surface — and it rules in reliable access to what the designer actually shared, which is the app's entire job.

It also needs no model, no Apple Intelligence gate and no new SDK — and it gives the client app meaningful coverage on the strength of its own evidence rather than for symmetry.

Smallest useful version

One record: the current shared direction plus the next requested decision, cached per user, read‑only, with visible freshness. Not the whole studio rail.

Effort & dependency

M. A schema version bump with a real migration stage (the existing ones are empty), a cache write on successful fetch, and a freshness line in the UI.

Principal uncertainty

How stale is too stale for a design decision, and what the app should do when cached content has been superseded. That is a product ruling, not an engineering one — and it should be Leah's.

Success criterion

Share of client sessions that reach the shared direction without an error state, measured against today. Plus zero approvals committed from unrevalidated cache — enforced, not hoped for.

Where iOS 27 does belong — sequenced, not shelved

Once the toolchain lands, the narrow version of the tag reader is a genuine experiment: category only, as a third implementation behind the existing SmartGuessService protocol seam, measured against the Vision heuristic on a labelled set. No floor bump, no price fields, no commercial values.

And SpeechTranscriber (iOS 26, no AI gate) is a clean win whenever it is scheduled: Field's voice notes currently fall back to Apple's servers where on‑device recognition is unsupported, which means a private note about a client's budget can leave the device today.

The failure mode worth naming

@Generable guarantees the shape, not the values. Published structured‑output benchmarking shows models at ≥96% on structure dropping to 0.69–0.83 value accuracy. A specimen draft has four near‑synonymous string fields — colorway, materialNote, finish, note — which is the documented worst case for field confusion.

A structurally perfect, confidently wrong spec sheet is worse than none, because it looks finished.

What OCR and barcodes already give you, free

Field already runs VNRecognizeText and a code scanner, producing .ocr and .code — the two most trustworthy sources in the enum, because they are verbatim reads with no generative step. Routing the same photo through a model collapses both into one .smartGuess.

The cheapest real win here is not a model: the N5 sheet currently calls its guess service with empty OCR and code arrays. It has a missing‑input problem before it has a model problem.

Build first: the extractor's front door

One route, on the surface the company ranks first, using a function that is already deployed, ACL‑hardened and SQL‑tested. It affects the designer portal now and Patina Field next — the same server extractor can later accept a captured tag photo, which is a strictly cheaper path to opportunity 7 than an on‑device model.

The experiment, and its bar

Run it against three real Middle West vendor PDFs hand‑keyed into a gold set first. Measure field‑level exact match: ≥95% SKU, ≥95% price, ≥90% maker. Time a full reviewed draft against manual entry — upload and waiting included, not just inference.

The uncertainty to validate before anything else

Can a model read this studio's paperwork accurately enough to be worth reviewing? If a frontier model reading a clean vendor PDF cannot clear 95% on SKU and price, then Apple's ~3B on‑device model reading a phone photo of a creased tag on a job site certainly cannot — and the company learns that for the price of one route, instead of an SDK upgrade, a CI bump, a floor cut and a permanent second code path.

Two questions only Kody and Leah can answer, and both gate work above: which phones the crew actually carry (the house census, already owed), and what the studio would genuinely send to someone on a roof.
