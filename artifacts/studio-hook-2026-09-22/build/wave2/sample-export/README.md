`patina-studio-billing-local-dev-studio-2026-09-23.xlsx` and its manifest text,
built by the shipped row builder
(`apps/designer-portal/src/lib/document/studio-billing-export.ts`) from the
**local development seed** — not from Strata, and not from any studio's real
book.

Generated by a read-only script: one SQL read of the local Postgres using the
same selects and the same `studio_id` tenant leg the portal's fetch uses
(`studio-billing-export-download.ts`), handed to `buildStudioBillingExport`, then
written with the same six-line SheetJS assembly the portal performs. Nothing was
written to the database.

What the seed happens to hold, and what the file therefore shows:

- **1 invoice** for `Local Dev Studio` (INV-2026-0301, sent, $4,060 outstanding).
- **0 lines and 0 payments** — and the manifest says why: all three seeded line
  items belong to the two invoices with `studio_id IS NULL`
  (`invoices_with_null_studio_id = 2`, the 00318/00513 disclosure), which a
  studio-scoped file cannot claim.
- **1 client record**, admitted on the `studio_invoice` authorization path.
  `client_records_without_studio_path = 5` — five roster rows the co-member RLS
  returns with no unambiguous path into this studio, left out rather than swept
  in by union.

`apps/designer-portal/src/lib/document/__tests__/studio-billing-export.test.ts`
carry the cases this seed has no rows for: a second studio's invoices, lines and
payments; a payer whose name resolves only through the 00588 roster ladder;
