Clear interaction model. Two architecture corrections.

What the prototype retains

  • The app is a field instrument and coach; reconstruction is downstream.
  • Coverage is visible during the walk, and the final gate points to an exact gap.
  • Typed spans bind field truth to two model points.
  • Context carries a spatial address into Capture Inbox.
  • The upload is checksummed, backgrounded, and resumable.

Scope authority applied

The P1 package says it wins when it conflicts with the SC deck. This walkthrough therefore allows closure below three anchors, stamps the room UNVERIFIED, and keeps the widest tolerance class visible.

Deployment conflict

The proposal names a homelab GPU and Coolify. Repository authority says that host is retired and must never receive deployments or traffic. Before implementation, item 9 must be rewritten for the approved Cloudflare/Supabase production topology or explicitly escalated as an architecture change.

P1/P2 language drift

The deck presents pose refinement, dense fusion, and splat training as the core reconstruction chain. The build package moves all three to P2. P1 UI and status copy should name only the anchor solve, corrected parametric drawings, and published tolerances.

Device boundary

LiDAR Pro devices get this capture flow. Non‑Pro devices need a separate context-only route that never uses the word “scan.” That route is specified but not expanded in this six-moment walkthrough.
