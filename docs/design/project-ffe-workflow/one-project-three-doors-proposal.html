Act I · The break02

What designers are telling us

The project has nouns. It has no obvious verb.

A designer can find FF&E, boards, the Library, and captures. What she cannot reliably find is the continuing act: add this to the project I am holding.

ProjectNo rooms means no item action

“No FF&E lines yet” appears, but “Add a line” exists only inside a room. The visible action is “Add room.”

→
BoardsThe first board is invisible

If a live project has no board, the entire Mood boards section returns nothing—no empty state and no “New board.”

→
LibraryPlacement loses the room

Card → Piece Room → Add to a project → project row. The item lands unassigned, and the designer must refine it later.

Board → FF&E breaks after conversion“Send to the schedule” writes only to proposal items and is suppressed on project boards.
Library import is global“Import a list” populates My Library; it cannot target a project or room.
The fastest placement is hidden⌘K → Ask the Engine → Place works, but is not advertised beside Project · FF&E.
The clipper is ahead of the portalIt already supports Library, project inbox, existing slot, and new FF&E line destinations.
Diagnosis: the first failure is continuity and visibility across capabilities Patina already owns. Completing the loop also needs one deliberate backend link: board placements must reference a project selection instead of becoming disconnected pins.

Act I · The work03

Professional interior-design flow

The normal flow is a loop that becomes more specific.

The formal stages are stable; the hand between them is not. Designers collect, compose, compare, replace, and return before a selection is ready to buy.

01Brief

Rooms, use, budget, retained pieces, responsibility.

02Concept

References, palettes, materials, visual direction.

03Source

Products, alternates, dimensions, price, lead time.

04Specify

Room, quantity, finish, vendor, code, cost summary.

05Approve

Present options, receive item-level decisions, revise.

06Procure

Quote, authorize, order, track, receive.

07Install

Place, inspect, punch, preserve the final record.

Collect loosely⇄Compose visually⇄Commit progressively
Early

An image and source link are enough to keep moving.

Middle

Room, category, quantity, finish, price, and alternatives become known.

Late

Approval, authorization, vendor and delivery state attach to the same selection.

Sources: CIDQ · BIID FF&E · NAVFAC FF&E procedures. Synthesis is Patina's inference.

Act IV · The anatomy13

Behavioral contract

Author once. Place many. Advance in place.

01Captured

Reusable Library product keeps source and provenance.

02Project selection

Project-specific room, quantity, finish, price snapshot.

03Board placement

Distinct placement IDs let one selection appear on several boards without twins.

04Decision

Internal disposition and client verdict keep actor, time, and board context; neither authorizes spend.

05Authorization

An immutable release instrument snapshots and references the selected project line.

06Procurement

Quoted, ordered, production, shipped, delivered, installed.

Alignment with The Authorized Schedule: author once, link never twin, derive never restate. A board creates a placement link; a project selection owns working facts; an immutable release instrument references its signed snapshot. Later change is void-or-supersede—not in-place replacement.
Act IV · Delivery14

Proposed sequence

Ship visibility first, then continuity, then the full loop.

Phase 1 · The doors

Make building obvious

  • Persistent “＋ Add to project” in the active project header.
  • Visible Boards section and New board empty state.
  • Reuse BoardsBuilder for project-native board creation.
  • Replace manual-only AddLineSheet with existing multi-source add controls.
  • Room and board destinations in Library placement.
Phase 2 · The shared record

Make every path converge

  • Add explicit selection↔board-placement identity, migration, and RPCs.
  • Keep disposition, client verdict, readiness, authorization, and procurement separate.
  • Project Library multi-select; import mapping, errors, and reconciliation.
  • Unsorted inbox and reference vs product/material semantics.
  • Make dedupe contextual: same source can be valid across needs.
Phase 3 · The loop

Advance without re-entry

  • Lightweight preference before binding authorization.
  • Board publish and preview-as-client controls.
  • Replacement history and alternates before release.
  • Release locks money/configuration; later change voids or supersedes.
  • Procurement continues on the authorized line.

Act V · The decision15

What the team needs to rule

Decide the model, not merely the button.

A louder CTA without shared continuity will make the fragmentation easier to enter. The recommendation is the whole sentence.

✓“＋ Add to project” persists wherever the project is open.Overview · room · board · selections
✓Boards are created, resumed, and understood inside the project.No invisible first board
✓Selections is the working lens; FF&E remains the operational schedule and issued artifact.Plain in the UI · canonical through procurement
✓A pin creates a working candidate; selection controls issued-schedule inclusion.Advance the record without flooding the formal view
