The mandate02

What designers are telling us

The feedback is not “we need one more button.” It is “I lose the project when I try to build it.”

“When I am viewing the project, it is not clear how to add a new item or how to create another board.”
01Boards, the Library, the clipper, and FF&E feel like separate destinations.
02The empty project names absence, but does not teach the first constructive act.
03Returning designers see status, not the most useful next piece of work.
04A louder global “create” would still leave routing, identity, and authorization ambiguous.
Design mandate: preserve Patina’s one-document-at-a-time paradigm while making project creation visible, reversible, and continuous across every source.

Design thesis04

The ruling behind every screen

Do not add a project dashboard. Make the Project section more capable.

The Document is the engagement. Boards are working rooms. The Library is a Studio room. FF&E lines are the operational record. Sheets handle focused construction without creating another place to go.

Information model06

Continuity requires explicit identity

Five identities keep one idea from becoming five conflicting records.

01 · reusableLibrary product

Maker, source URL, media, trade facts. Reusable across engagements.

product_id
02 · project truthProject selection

Room, quantity, configuration, client price, working facts and project decisions.

project_ffe_item_id

Canvas position, crop, scale, board, section. Many placements may reference one selection.

placement_id → project_ffe_item_id

Exactly what the client saw and judged in one immutable, nonbinding review edition.

review_item_id → frozen view
05 · authorityAuthorization line

Signed quantity, configuration, and money snapshot. Later change voids or supersedes.

authorization_item_id → source line

State model21

Behavioral contract · separate actors and consequences

Five axes. Never one overloaded “status.”

01 · designer

Disposition

  • Considering
  • Shortlisted
  • Rejected
How the studio is leaning. No client or commercial consequence.
02 · client

Verdict

  • Not shared
  • Pending
  • Looks good
  • Needs a change / question
Who saw what, when, and in which published review. Nonbinding.
03 · next act

Readiness

  • Draft
  • 2 facts missing
  • Ready for review
  • Ready for release
Derived from explicit gates; never a manual lifecycle status.
04 · authority

Authorization

  • Not released
  • Draft release
  • Sent to client
  • Authorized · executed
  • Voided / superseded
The actual draft → sent → executed instrument lifecycle. Released facts soft-lock before signature.
05 · logistics

Procurement

  • Specified
  • Quoted
  • Ordered
  • Production
  • Shipped · delivered · installed
The existing FF&E ratchet and line stamps remain operational truth.
Example: a chair may be “Shortlisted · client liked · ready for release · not released · quoted.” Any single label would hide the actor or imply a consequence that has not happened.

Change control23

Three authority boundaries · working, released, executed

Replacement changes at release—and changes again at execution.

Working line · editable

Before release

Replace or fill a placeholder while preserving why the design changed.

  • Link the alternate in the same selection thread
  • Keep the prior verdict as historical provenance
  • Reset the active verdict; review anew
  • Choose whether placements swap
Not released · no money locked
→
Release draft or sent · soft-locked

While the release is out

Released money and configuration cannot change—even before signature.

  • Void the release with a recorded reason
  • Then start the replacement selection
  • Reset active preference review
  • No authority to order yet
Draft / sent · void before change
→
Executed authorization · immutable

After execution

The authorized quantity, configuration, and money remain part of the record.

  • Start a superseding selection
  • Explain price and schedule delta
  • Collect a new authorization or addendum
  • After PO send, use a vendor change path
Executed · authority to order
Boundary rule: release requires void before working facts change; execution requires a superseding record. Once a purchase order is sent, replacement becomes a vendor change, claim, or new scope—not a rewritten line.
Privacy boundary24

Phase 0 · required before project-native working views

“Studio only” must be true at the data edge—not merely hidden in the interface.

The proposed experience assumes candidates, raw boards, trade facts, and markup are private until a designer deliberately publishes a review edition. Current access rules do not make that promise consistently.
