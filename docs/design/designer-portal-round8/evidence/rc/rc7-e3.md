## Reproduction and causes

- **RC7-E3-1 (high confidence, high severity):** `00868_round8_scope_composition.sql:127-135` defines `service_arrangements`, and `:431-435` requires a real key; there are no shipped catalog rows. Only synthetic arrangements appear in `supabase/tests/round8/scope_composition_body.psql:278`. The authorized designer refusal and non-author refusal still need their new browser gate. Do not silently import a test arrangement as product data.
- **RC7-E3-2 (high confidence, medium severity):** `apps/mobile/Capture/CaptureKit/CaptureKit/Sync/MarginNoteWrite.swift:18-53` encodes id, project, designer, body, anchor and capture only; `LocalCaptureSyncService.swift:741-770` invokes it. `margin_notes.subject_kind/subject_id` remain null; no Field scope/next-owner columns are written. Typed source and a deliberate authorized review assignment are missing; do not infer approval, revision, completion or sharing.
- **RC7-E3-3 (high confidence, medium severity):** `apps/designer-portal/src/components/document/margin-bodies.tsx:838-875` uses raw UUIDs as navigational names, despite the capture retaining `project_room_id`; the visible link must use the room's human label. The source link and stored room are not the same as an accessible label.
- **RC7-E3-4 — refuted (high confidence; no defect).** The hypothesis read a superseded function body. `00414_design_services_rail_completion.sql:57-131` redefines `begin_direction_from_discovery`: the seed is inserted with `document_kind='design_services'`, `commercial_state='draft'`, so the Direction is the agreement. Runtime read on the owned stack: `design_services|draft|draft`. `proposal-instruments.tsx:466-475` (retired send) applies only to the `legacy` experience (`commercial-documents.ts:126-143`); a design-services draft renders `service-agreement-instruments.tsx:250-268` (`Open the Contract Room`, `Review & send`), and `drafting-room.tsx:224` opens the agreement composer on the same row. `draft-proposal-opener.tsx:95-106` does insert a separate `design_services` row with no `parent_proposal_id`, but that is the ⌘K cold-start door ("no lead, no discovery"), not the Direction's path. Readback after countersign: `projects.proposal_id`, scope-edition and billing-authority `source_proposal_id`, and `client_discovery.seeded_proposal_id` all equal the Direction; `document_open` routes lead → relationship → project and Direction → project. `proposals.parent_proposal_id` is 0 for the Direction because no second document exists. **Residual risk for Kody (low, source-only, not run):** a designer who uses ⌘K `Draft a services agreement` for a household that already has a seeded Direction gets a second, unlinked draft, and the Direction stays an open draft. Proposed fix (not made): have the cold-start picker route a household with an open seeded Direction to `/drafting/<seeded_proposal_id>`.
