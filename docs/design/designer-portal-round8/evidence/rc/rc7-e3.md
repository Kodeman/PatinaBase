## Reproduction and causes

- **RC7-E3-1 (high confidence, medium severity; content ruling):** `00868_round8_scope_composition.sql:127-135` defines `service_arrangements`, and `:431-435` requires a real key. There are no shipped catalog rows, and that is deliberate: `00868:125-126` says presets are server-owned compositions and no product defaults are inferred from the illustrative contract examples. So this is a content ruling for Kody (which arrangements ship), not a code bug. Only synthetic arrangements appear in `supabase/tests/round8/scope_composition_body.psql:278`. The designer `arrangement_not_found` and non-author `scope_proposal_access_denied` refusals ran 2/2 per browser at `025320f85`. Do not silently import a test arrangement as product data.
- **RC7-E3-2 (high confidence, medium severity): schema gap plus writer gap.** Schema: `00874_round8_typed_subjects.sql:9-10` adds only `margin_notes.subject_kind`/`subject_id`; `margin_notes` has **no** scope or next-owner column. Writer: `apps/mobile/Capture/CaptureKit/CaptureKit/Sync/MarginNoteWrite.swift:18-53` encodes id, project, designer, body, anchor and capture only; `apps/mobile/Capture/Capture/Services/Sync/LocalCaptureSyncService.swift:741-770` invokes it, so `subject_kind`/`subject_id` stay null. The fixme (`rc7-e3-field.spec.ts:173-198`, comment above the test) reads `to_jsonb(n)->>'scope'` and `->>'next_owner_id'`, which are always null, and seeds its own note instead of using the product path. It cannot flip as written; rewrite it through the product path once a schema/writer ruling lands. Do not infer approval, revision, completion or sharing.
- **RC7-E3-3 (high confidence, medium severity):** `apps/designer-portal/src/components/document/margin-bodies.tsx:838-875` uses raw UUIDs as navigational names, despite the capture retaining `project_room_id`; the visible link must use the room's human label. The source link and stored room are not the same as an accessible label. The flip needs `f9e2c941d` plus `00902_round8_note_context_labels.sql` from branch `r8-rc7-fix-labels`; the expected link text is `Return to room · Living Room`. Scope and Next owner stay "Not recorded" after that fix; that part is RC7-E3-2.
- **RC7-E3-4 — refuted (high confidence; no defect).** The hypothesis read a superseded function body. `00414_design_services_rail_completion.sql:57-131` redefines `begin_direction_from_discovery`: the seed is inserted with `document_kind='design_services'`, `commercial_state='draft'`, so the Direction is the agreement. Runtime read on the owned stack: `design_services|draft|draft`. `proposal-instruments.tsx:466-475` (retired send) applies only to the `legacy` experience (`commercial-documents.ts:126-143`); a design-services draft renders `service-agreement-instruments.tsx:250-268` (`Open the Contract Room`, `Review & send`), and `drafting-room.tsx:224` opens the agreement composer on the same row. `draft-proposal-opener.tsx:95-106` does insert a separate `design_services` row with no `parent_proposal_id`, but that is the ⌘K cold-start door ("no lead, no discovery"), not the Direction's path. Readback after countersign: `projects.proposal_id`, scope-edition and billing-authority `source_proposal_id`, and `client_discovery.seeded_proposal_id` all equal the Direction; `document_open` routes lead → relationship → project and Direction → project. `proposals.parent_proposal_id` is 0 for the Direction because no second document exists. The ⌘K duplicate is recorded separately as RC7-E3-5.
- **RC7-E3-5 (medium severity, high confidence from source; reproducer written, not run): ⌘K cold-start forks the Direction lineage.** `draft-proposal-opener.tsx:95-106` inserts a new `design_services` draft for the picked household with no `parent_proposal_id` and no reference to the household's Discovery-seeded Direction. The sheet copy says "no lead, no discovery", and nothing checks `client_discovery.seeded_proposal_id`. If that second agreement executes, the project's `proposal_id` is the new row, the Direction stays an open draft, and the inquiry → Direction lineage forks: this is a workflow and lineage divergence, not just a duplicate. Reproducer: `test.fixme` "A03 cold-start agreement for a household with an open Direction offers continue-or-separate" in `rc7-e3-agreement-lineage.spec.ts` (`// DEFECT RC7-E3-5`). Proposed fix (not made; **ruling owed by Kody**): when the picked household has an open seeded Direction, show an explicit choice — _Continue the existing Direction_ (open `/drafting/<seeded_proposal_id>`) or _Start a separate commission_ (new row) — instead of silently creating a second draft or unconditionally reusing the Direction.
