## Reproduction and causes

- **RC7-E3-1 (high confidence, medium severity; content ruling):** `00868_round8_scope_composition.sql:127-135` defines `service_arrangements`, and `:431-435` requires a real key. There are no shipped catalog rows, and that is deliberate: `00868:125-126` says presets are server-owned compositions and no product defaults are inferred from the illustrative contract examples. So this is a content ruling for Kody (which arrangements ship), not a code bug. Only synthetic arrangements appear in `supabase/tests/round8/scope_composition_body.psql:278`. The designer `arrangement_not_found` and non-author `scope_proposal_access_denied` refusals ran 2/2 per browser at `025320f85`. Do not silently import a test arrangement as product data.
- **RC7-E3-2 (high confidence, medium severity): schema gap plus writer gap.** Schema: `00874_round8_typed_subjects.sql:9-10` adds only `margin_notes.subject_kind`/`subject_id`; `margin_notes` has **no** scope or next-owner column. Writer: `apps/mobile/Capture/CaptureKit/CaptureKit/Sync/MarginNoteWrite.swift:18-53` encodes id, project, designer, body, anchor and capture only; `apps/mobile/Capture/Capture/Services/Sync/LocalCaptureSyncService.swift:741-770` invokes it, so `subject_kind`/`subject_id` stay null. The fixme (`rc7-e3-field.spec.ts:173-198`, comment above the test) reads `to_jsonb(n)->>'scope'` and `->>'next_owner_id'`, which are always null, and seeds its own note instead of using the product path. It cannot flip as written; rewrite it through the product path once a schema/writer ruling lands. Do not infer approval, revision, completion or sharing.
- **RC7-E3-3 (high confidence, medium severity):** `apps/designer-portal/src/components/document/margin-bodies.tsx:838-875` uses raw UUIDs as navigational names, despite the capture retaining `project_room_id`; the visible link must use the room's human label.
