## Defects and privacy ruling

**RC7-E1-1 — C6 cross-request household projection (privacy decision needed).** `00895_round8_service_completion_household_reader.sql` admits a current signer on *any* sent request for the project to the C6 client completion projection; `e1_authority_matrix.sql` shows a profile linked to an older request, but not the completion's contributing `r4` request, can read it. This cross-request scope is visible in the migration predicate and header, but a separate authorization ruling for the breadth was not identified. Treat as a release privacy defect until the audience is explicitly approved; no migration or product change in E1.

The test-coverage defects in the old E1 suite (superuser/JWT conflation, nonexistent HTTP users, circular inactive REVOKE check) are corrected in source, **not yet verified**. The shared fixture's original native mutations still use postgres and cannot be claimed as authenticated-role proof. The print race covers only same-key replay, not distinct-key numbering or same-key/different-payload conflict.
