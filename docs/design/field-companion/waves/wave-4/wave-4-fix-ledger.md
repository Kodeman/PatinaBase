## ⚠ Four fixes ship with no test, and the reason is structural

**I-2, I-11, I-13, I-14 have no test because the app target has no test host.** `CaptureTests` is a
`unit_test_bundle` that declares `tests.add_dependency(kit)` and links **CaptureKit alone**
(`scripts/generate_project.rb:161-186`); every file in it is `@testable import CaptureKit`. Nothing
under `Capture/` — `LocalCaptureSyncService`, `VisitCloseOutboxDrainer`, `V4VisitReviewScreen`,
`SmartGuessSheet` — is reachable from a test at all. This is the ledger's own **C1** finding, and it
is why a 719/719 suite is not evidence that a row lands.

Where a decision could honestly be lifted into CaptureKit it was, rather than left unproven: **I-1**
(store scoping), **I-10** (classifier + orchestrator), **I-12** (composer rule) and **I-5** (copy
constant) are all covered. What remains app-side is wiring, one guard clause, three owner re-checks
and a view-performance change — and for those **the wave's device pass is still the only evidence.**

## Re-review round 2 — carried, recorded, no code taken

The scoped re-review of the fix set verdicted MERGE-WITH-FIXES again. Its MUST and SHOULD findings
were patched (see the round-2 table below). These are the ones deliberately **not** taken, recorded so
none is re-discovered as an omission.

- **R-5 — `00545`'s replacement assertion is weaker *in kind*, and the write moved rather than vanished.** Pinning the constraint by `conkey` + four `LIKE` probes proves the definition *mentions* the values; it does not prove an INSERT succeeds. That is a genuine loss against the block it replaced. It was still the right trade — the removed block could commit DDL after a failed check, which is a worse failure than a weaker check — but the behavioural INSERT now lives in `time_entry_field_visit_source_test.sql`, which **does** write `auth.users` locally. So the wave did not eliminate the `auth.users` dependency; it moved it from a migration that runs on prod to a test that runs in a rolled-back local transaction. That is the actual claim, and the earlier ledger wording oversold it.
- **R-11 — a silent visits read makes a failure indistinguishable from no data.** W-2's `errorSurface: 'silent'` means a designer whose `margin_items`/visits read 42501s sees an empty Visits block, which reads as *"no visits on this project"* — a wrong fact stated confidently, rather than an error. The alternative (a toast on every project spread) is worse, and FC-R10 asks for a block that degrades to nothing. But *empty* and *broken* looking identical is a real cost. **Flagged for Kody's sign-off**, not silently accepted.
- **R-12 / R-13 / R-14 — the P-1 falsifier's own limits.** Case 8a revokes and re-grants inside the transaction, so it proves the *dependency* exists; it does not prove prod currently holds the grant (nothing local can), it skips itself when run as an owner who bypasses grants, and a blanket seed re-grant would mask exactly the absence it is testing for. The case is worth what it is worth and no more.
- **R-17 — I-5's new menu row ships on the unreachable sheet.** *"Punch item filed — file another?"* is correct copy on a surface no shipping build can open. It rides with I-4 and becomes visible whenever that ruling lands. — **CLOSED 2026-09-01 by FC-R23.** The row is now rendered by `FieldVerbRow.punchFiled` on the C3 card, above the still-present punch verb, and its position and re-open are pinned by test.
- **R-20 — the same unguarded-`Intl` class exists twice more, pre-existing and out of scope.** `desk-derivation.ts:503-517` (`fmtDayTime`, `timezone || 'UTC'`) and `ceremony-schedule.ts:85-95` (`fmtCeremonySlot`, `timeZone: timezone || undefined`) both pass a nullable stored timezone straight into `Intl.DateTimeFormat` with no `try`. Both predate this wave. The blast radius is smaller than W-1's — those zones are ceremony/desk records rather than a value a phone chose — but the failure shape is identical and neither route group has an error boundary either. **Owed to Kody as its own small fix; not taken here** because it is outside the wave and would widen a fix round into unrelated surfaces.
