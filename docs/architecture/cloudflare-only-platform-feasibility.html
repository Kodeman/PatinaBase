Can Patina leave Supabase?

A Cloudflare-only platform is technically feasible. It is not a vendor swap; it is an auth, data, and authorization re-platform.

Scope: “Cloudflare-only” means hosting and control-plane primitives—not Stripe, APNs, email/SMS, accounting, or device-platform vendors.

The four hard gaps05 / 14

The difficult work sits at the seams.

“Same features” is the wrong test. Preserve the same invariants.

01

Customer identityPassword lifecycle, social login, MFA, account recovery, abuse controls, session revocation, and mobile token handling become Patina’s responsibility.

02

Database authorizationD1 does not provide Postgres row-level security. Every read and write must pass an application policy boundary with no bypass path.

03

Relational behaviorD1’s SQLite model, 10 GB/database ceiling, and single-threaded execution change partitioning, concurrency, extensions, SQL, transactions, Prisma, and operations.

04

Realtime coherenceDurable Objects plus hibernating WebSockets fit room coordination, but provide no database CDC. Changes become explicit domain events with recovery and ordering rules.

These gaps compound: identity → policy → data → eventsSecurity review is a release gate

Data model implications07 / 14

Do not pour Postgres into a SQLite-shaped mold.

The durable design unit becomes the bounded context. Each domain owns its database, API, authorization rules, and emitted events.

Keep relational

Strong local invariants

  • Foreign keys inside a context
  • Short, explicit transactions
  • Idempotency keys
  • Append-only audit records
Make explicit

Cross-domain behavior

  • No cross-database joins
  • Denormalized read models
  • Event-driven propagation
  • Reconciliation jobs
Migration consequence

SQL compatibility is only the first test.

Inventory Postgres extensions, stored procedures, triggers, policy expressions, JSON operators, transaction assumptions, Prisma queries, and reporting joins. Classify each as retain, rewrite, or retire.

Agent queue audit guarantees must survive the movePayable-state tables remain the source of truth

Security model08 / 14

Replace implicit trust with one guarded path.

Identity

Authenticate at the edge

Issue short-lived sessions, rotate refresh tokens, bind privileged actions to recent authentication, and preserve revocation.

Authorization

Policy before repository

Typed domain actions evaluate actor, tenant, resource, and purpose. D1 bindings remain inaccessible outside approved repositories.

Evidence

Audit every transition

Carry actor identity through queues and workflows. Preserve append-only audits, request IDs, and traceable administrative access.

Browser / app → session verifier → policy engine → domain service → D1Deny by default · test policy matrices
Cloudflare Access is an internal-access product, not a direct GoTrue replacementIndependent threat model required

Migration path09 / 14

Strangle by domain; never big-bang the database.

0 · Discovery

Prove constraints

Inventory SQL and policies. Benchmark representative queries. Threat-model auth.

1 · Foundation

Build paved road

Identity gateway, policy SDK, migrations, observability, audit envelope.

2 · Low-risk pilot

Move one context

Choose read-heavy, reversible data. Shadow reads and compare behavior.

3 · Domain waves

Expand gradually

Dual-write only where bounded. Backfill, reconcile, cut over per context.

4 · Core cutover

Retire Supabase

Move auth and final write paths only after rollback drills and acceptance gates.

Every wave needs rollback, reconciliation, and behavior probesMobile token compatibility spans release cycles

Kill criteria

Stop the full-exit track if…

  • Representative transactional workloads fail acceptance tests.
  • Policy parity cannot be demonstrated automatically.
  • Customer auth requires unacceptable bespoke ownership.
  • TCO does not justify migration and ongoing labor.
  • Rollback cannot be rehearsed without data loss.

Recommendation13 / 14
Recommended now

Authorize a bounded spike, not a migration.

Spend 6–8 weeks answering the few questions that can invalidate the thesis before committing to a multi-quarter program.

Gate A · Data

Capacity + load

Prove D1 size/headroom and 2× representative write load; document SQL incompatibilities.

Gate B · Security

Policy + identity

Demonstrate authorization parity and make an explicit customer-identity decision.

Gate C · State

Recovery + money

Prove Durable Object recovery/order and payment idempotency under replay.

Gate D · Operations

Restore + decide

Run a restore drill, then choose hybrid, D1 + external IdP, or literal Cloudflare-only.

Default hypothesis: hybrid may dominate full exit on risk-adjusted valueDecision owner: architecture + product + security
