01 — The Problem

Cowork runs in a folder.
You need to run a business.

The vendor pipeline you built in Cowork works. Scorecards get generated, research briefs land in folders, scheduled tasks pull new prospects overnight. But the interface is a file explorer and a chat window. You can't glance at it and know where you stand. You can't see the whole pipeline at once. You can't hand Leah a view that shows only the vendors waiting for her aesthetic judgment.

The Admin Portal doesn't replace Cowork — it gives it a face. Cowork is the engine room. The portal is the bridge. You steer from here, and the engine does the work below deck.

"The portal sees what Cowork does. Cowork does what the portal asks. Neither is useful without the other."
Integration Architecture Principle

02 — The Integration Architecture

How the portal and Cowork talk to each other

The architecture is a three-layer stack. Humans make decisions in the portal. Cowork executes autonomous tasks against the file system and the web. A shared database (Supabase) is the single source of truth that both read from and write to.

Human Layer — Decisions & Judgment
Kody — Admin Portal Scores vendors, triggers Cowork tasks, reviews pipeline, manages onboarding phases
Leah — Admin Portal (Filtered View) Aesthetic scoring, relationship notes, brand gut-checks, outreach conversations
↕
Portal Layer — Visibility & Control
Pipeline Dashboard Kanban-free overview of all vendors by stage and score
Vendor Detail Rubric scorecard, Cowork activity log, onboarding tracker, notes
Task Launcher Trigger Cowork tasks from portal with pre-filled context
↕
Cowork Layer — Autonomous Execution
Discovery Agent Scheduled web research, prospect identification
Research Agent Vendor scoring, pre-call briefs, data quality audits
Outreach Agent Email drafts, pitch material, follow-up scheduling
Onboarding Agent Feed ingestion, data normalization, image processing
↕
Data Layer — Single Source of Truth
Supabase · vendors Pipeline stage, scores, contacts, notes, timestamps
Supabase · cowork_tasks Task queue, status, outputs, linked vendor_id
Filesystem · /vendor-pipeline Scorecards, briefs, feeds, images (Cowork read/write)

The Data Contract

When the portal triggers a Cowork task, it writes a row to cowork_tasks with a task type, linked vendor ID, and any context payload. Cowork's scheduled polling picks up new tasks, executes them, and writes results back — both to the database (structured outputs like scores) and to the filesystem (documents like briefs and scorecards). The portal reads both sources to render the UI.

No webhooks. No real-time sockets at MVP. The portal polls cowork_tasks every 30 seconds for status updates, and shows a Cowork activity indicator when tasks are in flight. Simple. Debuggable. Good enough until you need more.

03 — The Task Flow

A vendor moves through five stages.
Here's who does what.

Each stage has a human trigger and a Cowork execution. The portal shows the result. The color on the left tells you who's acting at each step.

Cowork

Prospect Discovered

Scheduled weekly task scans trade publications, furniture directories, and industry social accounts. New brands matching Patina's category gaps are added to the pipeline with an initial data snapshot. Stage: Discovery.

Cowork

Auto-Score (Dimensions 1–4)

Cowork researches the vendor's website, trade program pages, retail presence, and public pricing. Fills in the operational half of the rubric scorecard. Flags missing data. Saves the scorecard to the filesystem and writes the numeric score to the database.

Kody

Review & Triage

Kody opens the pipeline dashboard, sorts by score, reviews auto-scored vendors. Adjusts scores where Cowork's public research missed nuance. Passes qualifying vendors to Leah's queue.

Leah

Aesthetic & Relationship Scoring (Dimensions 5–8)

Leah sees only vendors that passed the operational gate. She scores brand alignment, category value, sustainability, and relationship warmth. Her interface is stripped down — images, brand story, gut-check sliders. No spreadsheets.

Cowork

Pre-Call Brief Generated

For vendors scoring GREEN (400+), Cowork generates a one-page research brief: brand story, key contacts, product highlights, current retail channels, suggested talking points. Saved as PDF. Stage advances to Outreach.

Leah

Outreach Conversation

Leah makes the call. She logs outcome notes directly in the portal. If the vendor wants to proceed, Kody clicks "Begin Onboarding" — which triggers the next Cowork sequence.

Cowork

Data Intake & Normalization

Vendor sends their product feed (CSV, PDF line sheet, Dropbox link). Cowork ingests it: maps fields to the Patina product schema, downloads and renames images, flags missing data, generates an import-ready dataset. Stage: Onboarding.

Kody

Quality Review & Go-Live

Kody reviews the normalized data in the portal, approves the import, and publishes the vendor's initial SKUs to the platform. Stage: Live. Cowork schedules recurring feed sync if the vendor provides an ongoing data source.

04 — Navigation Architecture

Four zones. One sidebar.

The admin portal serves the founding team — two people managing a pipeline, a catalog, an ML system, and a business. The navigation reflects that scope without pretending to be enterprise software.

Zone 1

Aesthete Engine

Style Taxonomy · ML Model Health · Training Data · A/B Tests · Recommendation Accuracy · Designer Teaching

The sidebar groups these into collapsible sections. The Vendor Pipeline is expanded by default because it's the primary workflow right now. As the business grows, other zones grow with it. The shell doesn't change — only the content inside each zone deepens.

07 — Leah's Review Interface

Stripped to the essential question.

Leah doesn't need the pipeline table. She doesn't need Cowork task logs. She needs to look at a brand and answer four questions: Does this fit? What categories does it fill? Is it sustainable? Do we have a relationship? Her view shows only vendors waiting for her scores, presented as brand stories — not spreadsheet rows.

The interface shows one vendor at a time, full-width. Product imagery from their website. Their brand story. Then four sliders — one per dimension — with Leah's vocabulary as the labels, not rubric numbers. She scores, adds a gut-check note, and hits "Next." The rubric math happens in the background.

09 — Implementation Plan

Build the dashboard first.
Everything else follows.

Four sprints. Each one delivers a usable surface. The pipeline dashboard works on day one because the data already exists in your Cowork folder — you're just putting a face on it.

01

Sprint 1 — Pipeline Dashboard + Data Bridge

Supabase vendors table + cowork_tasks table. Migrate existing scorecard data from Cowork folder into the database. Build the pipeline table view with sorting, filtering, and score display. Next.js 15 at admin.patina.cloud. Ship week 2.

02

Sprint 2 — Vendor Detail + Leah's Review

Vendor detail page with rubric visualization, onboarding phase tracker, and notes. Leah's stripped-down review interface with slider scoring. Cowork activity log reading from the task table. Ship week 4.

03

Sprint 3 — Task Launcher + Cowork Bridge

Portal can write tasks to the queue that Cowork picks up. "Generate Brief" button creates a task row. "Re-score" triggers auto-scoring. "Begin Onboarding" spins up the data intake workflow. Cowork polls the table every 30 seconds. Ship week 6.

04

Sprint 4 — Feed Monitor + Catalog Integration

Live vendor feed sync status. Product catalog intake queue showing normalized products awaiting review. Connection from approved vendor products into the main Patina catalog. The pipeline's output becomes the catalog's input. Ship week 8.

Tech Stack

Same stack as the rest of the strata monorepo. Next.js 15, React 18, TypeScript, Tailwind CSS, Supabase. The admin portal lives at apps/admin-portal/ in the monorepo. Cowork integration is database-mediated — no direct API calls between the portal and Cowork. Cowork reads and writes to Supabase via its filesystem scripts. The portal reads and writes to Supabase via its Next.js server actions. They never talk to each other directly. That's the entire architecture.

The portal makes the invisible visible.

Every vendor Cowork discovers overnight shows up in your pipeline by morning. Every score Leah enters reshapes the priority order in real time. Every task in flight has a status you can see without opening a terminal. Every brief, every scorecard, every feed sync — surfaced through typography and whitespace instead of buried in a folder tree.

Cowork is still doing the heavy lifting. The portal is just the window that lets you see the work happening — and the steering wheel that lets you point it where it needs to go next.

Build the dashboard. Migrate the data. Put a face on the engine. The rest follows.
