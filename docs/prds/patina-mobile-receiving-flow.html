Mobile Receiving FlowThree photos, two taps, done

The phone is the receiving tool. Leah stands next to a carton on her studio floor. The flow optimizes for the 95% case — item arrives, looks fine, log it and move on. The exhaustive inspection checklist surfaces only when something's wrong. v1 confirmed: phone-only, designed at 375px (iPhone), designer-receiving, no third-party portal.

Platform

Mobile web · 375px primary · iOS/Android

Audience

Designer (studio owner) · Solo or studio team

Target session time

30 seconds happy path · 2 minutes with damage

Design principles

Built for standing next to a carton.

Receiving isn't done at a desk. It's done on a studio floor or in a garage with one hand free, sometimes in a rush, sometimes after hours when the delivery driver is impatient. Every design decision optimizes for those conditions. Speed is courtesy.

01
Big targets, thumb-zone actions
Primary buttons are 48–56px tall. Critical actions sit in the bottom third of the screen where the thumb reaches naturally. No tap targets smaller than 44×44px. Designed for one-handed use.
02
Happy path is silent
Item arrived, count matches, no damage: 3 taps and done. No checklist questions, no friction. The system trusts the designer. The exhaustive inspection appears only when she taps "Issue found."
03
Photos are the truth
Three photos minimum on every receive (overall, label/PO, packaging condition). Optional additional photos for any concern. Photos timestamp and geolocate automatically. They're the warranty insurance.
04
Damage path is fast too
Even the not-happy path optimizes for speed. Tap "Issue found" → mark issue type → take 2 additional photos → describe in 1 sentence (voice-to-text default). Auto-drafts the vendor claim email. Two minutes.
05
Offline-tolerant
Photos and notes capture locally first, sync when connection returns. The studio garage might not have great signal. The flow never blocks waiting for a network round-trip.
06
Receipt is reassurance
After logging, a clean success state. Strata Mark. "Logged." Photo grid for verification. Direct link to the item in the desktop workspace. Leah closes the app knowing it's done.

The Damage Path · 5% of arrivals · The expensive 5%

When something's wrong.

Industry research is unanimous: damage discovered later (on install day, weeks after arrival) is the most expensive failure in procurement. Catching damage at receipt is the single highest-leverage moment in the entire workflow. The damage path is designed to make doing-the-right-thing easy enough that Leah doesn't skip it under time pressure.

Technical specification

What Claude Code needs to build.

The flows above are user-facing. Below is the implementation spec — component dimensions, interaction patterns, capture targets, data model touchpoints, and edge cases. This is the contract for what Sprint 2 ships.

Viewport & layout

Primary viewport 375px — iPhone SE/12 mini baseline. Test 390px (iPhone 14), 414px (Plus models).
Min tap target 44 × 44 px per Apple HIG. Primary actions ≥ 56px tall.
Thumb zone Primary CTAs in the bottom third of the screen. Sticky bottom bar with linear-gradient fade above.
Safe areas Respect iOS notch + home indicator. Use env(safe-area-inset-*) for all positioning.
Orientation Portrait only. Camera screens hard-lock portrait.

Camera & photo capture

API Native <input type="file" accept="image/*" capture="environment"> for v1. Native MediaStream API in Phase 2 for live overlay.
Compression Resize to 1600px on longest edge. JPEG quality 0.85. Average file 200-400 KB.
EXIF Preserve timestamp + GPS. These are the warranty audit trail.
Offline storage IndexedDB. Up to 50 MB of pending photos. Sync queue processed on reconnect.
Upload target Supabase Storage. Naming: receiving/{po_id}/{photo_type}-{idx}.jpg

Voice-to-text

API Web Speech API (SpeechRecognition) for v1. Falls back to native keyboard if browser unsupported.
Language en-US default. Configurable per user in Settings.
UX Hold-to-record. Release stops. Tap-to-edit in text field after transcription. Mic stays available for re-recording.
Privacy Audio not stored. Only the transcribed text persists.

State management

Flow state Zustand store. Persists to sessionStorage so a mid-flow refresh doesn't lose progress.
Network state navigator.onLine + service-worker fetch interception. Visible offline indicator when disconnected.
Pending operations Queue in IndexedDB. Background sync via service worker on reconnect.
Optimistic UI All state transitions show immediately. Sync errors surface as non-blocking toast.
Idempotency Each receive operation generates a client-side UUID. Backend deduplicates if the sync retries.

Data model touchpoints

receive_event New table. Fields: id, po_id, received_at, received_by_user_id, status (clean/damaged), notes, lat, lng, client_uuid.
receive_photo New table. Fields: id, receive_event_id, photo_type (overall/label/packaging/damage_close/damage_context), storage_path, taken_at, exif_json.
damage_claim New table. Fields: id, receive_event_id, issue_types (jsonb), description, claim_email_sent_at, vendor_response, disposition (accept_store/refuse/reorder), resolved_at.
po (existing) Status transitions via receive_event: Shipped → Delivered (clean) or Shipped → Delivered with damage. Auto-pause balance payment if damaged.
payment_record (existing) Balance state transitions: pending → due on Delivered. due → paid on payment confirmation. due → paused on damage claim.
notification Trigger to studio owner on claim sent, claim response received, claim resolution.

Edge cases & error handling

No PO match If item arrives without a scheduled PO (rare): "Log unscheduled delivery" flow. Manually pick the project + item. Same photo flow.
Multi-carton split delivery PO with multiple cartons can be received partially. Flow shows "1 of 3 cartons" and allows partial receive. Reminder set for remaining cartons.
Wrong item arrived "Issue found · Wrong item" triggers expanded flow: which item is this actually? Photo of label. Auto-drafts vendor email with mis-shipment evidence.
Camera denied permission Fallback to file picker (existing photos). Banner explains why camera helps. Doesn't block the flow.
Offline at receive Full flow works offline. Indicator "Will sync when online." On reconnect: silent background sync, success toast.
Carrier requires signature Out of scope for v1. Leah signs the driver's device separately. Patina doesn't capture POD signatures in v1.
Claim email delivery failure SMTP failure surfaces inline. Claim stays in "draft" status. Retry available. Sent emails BCC'd to studio owner's email for backup.
Vendor has no email on file Block claim send. Direct Leah to update vendor record with claims email address. One-tap flow to add it inline.
"The most valuable thing the mobile receiving flow does isn't speed. It's making the right thing easy enough that Leah does it every time — even when she's tired, even when the driver is impatient, even when the carton looks fine and she could just sign and move on. The flow earns its place by being faster than not using it."
