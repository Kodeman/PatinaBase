Orientation

What the engine is

The Aesthete Engine is Patina's taste system: a shared 768-dimensional style space (nomic-embed-text-v1.5 + nomic-embed-vision-v1.5, int8 ONNX) in which products, client quiz results, designer taste, and the house point of view all live. The client-facing money path — style quiz → top-ten product matches with human-readable "why" phrases — is pure SQL over pre-computed vectors (86ms end-to-end, match RPC p95 12ms), so the inference service being down is a non-event for it.

Around that core sits a Bradley–Terry taste model over a 94-dimensional interpretable basis, refit nightly per designer; Claude-drafted product DNA (drafts never overwrite designer-owned rows); a jobs outbox for all machine work; and weekly drift audits. The design document, v1.0.3, is docs/prds/AE/aesthete-engine-system-design.md (18 sections).

Recommendation

Stay on this footprint. It is already live and green; the hot path is pure SQL, so container availability only affects background embedding, refit, and ask; the container is already paid for by the Room View program; and there is no traffic yet that would justify more.

Cost picture

All figures are estimates — verify against current Cloudflare and Anthropic pricing before budgeting.

  • Cloudflare Workers paid-plan baseline.
  • Containers bill on active seconds — with sleepAfter 1h and today's near-zero duty cycle, container cost is minimal.
  • Ceiling if pinned warm 24/7 at standard-3 is roughly $100–160/mo.
  • Supabase: AE adds negligible load to the existing Strata plan.
  • Claude DNA drafting (design-doc estimates): ~$0.013/product with Haiku drafts; $40–75 one-time for a 5k-product Batches backfill. DAILY_BUDGET_USD + aesthete_spend_ledger cap daily spend.

Deploy procedure — and the one gotcha

The model weights (224 MB int8 ONNX: text 137 MB, vision 97 MB) are host-exported and gitignored. Dockerfile.cf COPIES models/ from the host, so a worker deploy REQUIRES make export (≈1.5 GB download, pinned HF revisions, manifest sha256) before wrangler deploy. A fresh clone without that step ships a broken image. Deploy order when things change:

  1. Migrations.
  2. Edge functions — scripts/deploy-edge-functions.sh covers all five.
  3. Worker — cd infra/inference-worker && npx wrangler deploy.
  4. Portals — ./infra/deploy-portal.sh.

Scale / split triggers

  • Raise past the singleton — or split the AE embed lanes from the Room View conversion lanes into separate containers — when embed backfills start contending with scan conversions.
  • Add a custom domain / route if the workers.dev URL becomes a policy issue.
  • Revisit Typesense only if aesthete_search FTS falls over — it was deliberately deferred.

Watch items

Risks & watch items

  • Match quality is unvalidated at scale. Every green bar so far ran on ≤12 seed products and synthetic judgments; the W4 designer validation sprint is the actual quality gate and hasn't run.
  • Quiz personalization is degraded until quiz-image embeddings exist. Style vectors currently come from option loadings + style centroids over a 3-product catalog.
  • Analytics are dark in prod. With POSTHOG_KEY missing, you can't yet see the funnel behavior you'd use to prioritize Phase C.
  • One shared container couples AE and Room View. A scan-pipeline deploy or crash restarts the embedding lane too — acceptable now; the split is the documented trigger.
  • Stale docs are a footgun. The AE runbook / prod-readiness docs predate the Cloudflare migration and describe a dead deploy path.
  • Model weights exist only on Kody's machine + the baked images (gitignored, HF-pinned). Re-export works from the manifest, but the make export step is undocumented in the runbook.
