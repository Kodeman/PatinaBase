The shape of the design

Five decisions everything else follows from

One 768-d shared space

nomic-embed text + vision v1.5 aligned pair (Apache-2.0, CPU-viable). Quiz answers, product photos, portfolios and asks — one cosine. Keeps every existing vector(768) column and all five 00008 RPCs.

The hot path is pure SQL

Quiz → top-10 makes zero inference calls. Quiz imagery pre-embedded; client vector assembled in-DB from anchors; matching is one RPC. Inference down = non-event for the demo.

Taste is ~94 readable numbers

Bradley–Terry preference weights over an interpretable basis — not a raw-768 vector 300 judgments could never train. Makes "Your Eye" readable and deviation-from-house free.

Scores & vectors never fight

Embeddings are immutable model outputs. Designer edits flow through a deterministic caption re-embed; spectrums are their own scoring channel — sliders change matches instantly.

One new runtime piece

A slim stateless ONNX inference worker for ingestion-time embeddings. Everything else: Postgres RPCs, Deno edge fns on the existing pg_cron bridge, one shared quiz package.

And one deletion

The never-deployed Python service dies. Salvage: scoring-weight priors, MMR diversifier, rule-predicate schema, the score-breakdown shape. Its mocks, dim bug & OpenSearch stub die with it.

The codebase is further along than the brief assumes

The six spectrums are a live table (product_style_spectrum, −1..1, with calibration anchors). Full teaching system: queue auto-trigger, sessions, 3-touch validations, portal UI with the 6-slider deep editor. A quiz→recs path already serves iOS (process_style_quiz + get_recommendations — signatures frozen). A behavioral stream already flows (interactions → engagement_events). Three-layer catalog RLS + the v_aesthete_*_input read-contract views.

Half-wired — finish it

Aspirational — decide honestly

No Typesense, Qdrant, or OpenSearch exists anywhere — the brief's "Typesense alongside" is doc-ware. Decision: Postgres FTS (already live) behind a single aesthete_search() seam Typesense can replace in Phase 2 without touching callers.

The constraints that bind

Single Coolify host, no GPU. Redis capped at 256 MB. pg_cron → edge-function bridge with a 60-second window. Product law from The Document: engine-as-presence, de-gamified, "Designer-Taught Intelligence" — never "AI."

Scale honesty

Products 10³–10⁴ · clients 10³ · designers 10¹ · judgments 10³–10⁴. The whole vector working set fits in shared_buffers. Design for these numbers; keep seams for 10×.

The aesthetic space

Every entity is one aesthetic point

A = ( v, s, c, a, m, β ) │ │ │ │ │ └─ budget posture (clients only — never a taste feature) │ │ │ │ └───── material affinities {wood: .8, metal: .2, …} │ │ │ └───────── archetype weights over the 12 seeded styles │ │ └───────────── per-dimension confidence ∈ [0,1]⁶ │ └───────────────── six spectrums ∈ [−1,1]⁶ — the shipped table └───────────────────── unit dense vector ∈ S⁷⁶⁷ (nomic v1.5 space)

Products

v = normalize(0.65·mean(images) + 0.35·caption) — the caption is a deterministic template from DNA fields, not retailer SEO text. Canonical spectrums stay designer-owned.

Clients

Assembled in SQL: chosen quiz-image embeddings (pre-computed) blended 50/50 with archetype centroids. No model in the loop.

Designers & house

Portfolio geometric median seeds v_D; judgments refine θ_D nightly. House = curated exemplar centroid, then earned consensus.

Category dominance (CLIP sees what, not how it reads) is neutralized by category-conditioned matching + the fused caption now, and a learned 768→64 style projection in Phase 2 — which also makes "slider nudges the vector" real via concept directions.

System overview

Topology: Postgres at the center

One wire contract, two hosts

The RPC is the interface — identical from the external marketing repo and the client portal. The shared packages/aesthete-quiz (plain-fetch, no supabase-js dep) is convenience.

Nothing on this path touches the inference worker. ⌘K asks degrade to FTS with "the Engine is resting." Jobs queue and drain on recovery.

Model & cost

Haiku 4.5 bulk ≈ $0.011–0.013/product; Sonnet escalation when confidence < 0.6; Batches API for backfill — a 5k catalog ≈ $40–75 one-time. Daily spend ledger parks the queue at budget.

Calibrated, not vibes

Cached system prefix carries the six spectrum definitions, the 12-archetype taxonomy, and few-shot anchor products with gold scores — the cross-product consistency mechanism. Monthly anchor re-score; affine post-correction once validations accumulate.

Drafts never become canon

Claude writes product_dna_drafts + ml_predicted styles — never the designer-owned spectrum row. Scorer reads canonical-else-draft at reduced confidence, so the whole catalog matches while the queue is worked.

The centerpiece, made trainable

Your eye is ~94 numbers you can read

A designer produces hundreds of judgments, not millions. So taste is a Bradley–Terry preference weighting over an interpretable basis — not a raw-768 vector that 300 pairs could never train.

φ(p) = [ spectrums·conf (6) · archetypes (12) · materials (10) · patina (1) · craft (1) · zₚ (64) ] — no price, no budget features: taste can never learn to proxy budget — P( i ≻ j │ designer D ) = σ( θ_Dᵀ (φᵢ − φⱼ) ) nightly refit: θ_D = argmin Σ wₜ·log(1+exp(−yₜ·θᵀΔφₜ)) + λ‖θ − θ_H‖² wₜ = weight·exp(−Δt/180d) — corrections count 2×, taste drifts, old pairs fade prior mean = the house ⇒ deviation-from-house = θ_D − θ_H, for free
judgments are truth · θ is a cache · refits are replayable online preview moves "Your Eye" today, overwritten tonight explicit rules stay rules and emit 0.5-weight pseudo-pairs
How much a designer's vote counts

Reliability = predictability, not low variance

ρ_D — can the model predict them?

Temporal-blocked cross-validation: fit on earlier judgments, score later ones → pairwise AUC, shrunk hard at low n. A designer with strong, wide-ranging taste is not "unreliable" — an unpredictable one is.

Blind repeat probes

~1 in 25 pairs is a previously judged pair, order-reversed, ≥ 14 days later. Agreement blends in at 25%. Invisible — no "consistency check!" copy (de-gamified law).

Drift is a feature

Recent-vs-trailing θ divergence surfaces as "your eye is shifting" in Your Eye — never a silent overwrite. Idle confidence decays; the portfolio seed never does.

Confidence by style — finally with a writer

Per archetype: local held-out accuracy blended with teaching-validation consensus, shrunk by n. Expert ≥ 0.7 · Advanced ≥ 0.4 · Learning below. This same nightly computation gives designer_teaching_stats.accuracy_score and match_impact_count their long-missing writers.

c_D(g) = n_g/(n_g+10) · [ ½·AUC_g' + ½·consensus_g ]

Named biases ride on top: standardized deviation ≥ 1σ, sign-stable across bootstrap refits, template-named ("Warms up cool pieces"), designer-editable — edits never write back into θ. A view + override layer; machine state stays honest.

The feature

The dial, made precise

w_eff = w · ρ_D · c_D(style)   ·   θ_blend = θ_H + w_eff · (θ_D − θ_H)

Blend at the preference-weight level — where confidence has clean semantics — not by averaging unit vectors. The dense blend tints only the ANN query.

Three stops

House / Blended / Designer's eye → w ∈ {0, 0.35, 0.9}. Anonymous quiz starts at pure house; an assigned designer raises it; "show me their eye" pushes high.

Self-limiting cold start

A new designer floors at ρ ≈ 0.15 (portfolio-only), so even w = 0.9 yields w_eff ≤ 0.14. The dial exists from day one — it bends results only as fast as the vector becomes real.

It earns its clicks

The 0.9 stop unlocks per-designer only when θ_D beats θ_H on their own held-out judgments by ≥ 5 points. The eval metric and the product gate are the same number.

And the hard bound: taste enters scoring only through one additive term at weight 0.12. "Amplifies, never overrules" is a weight cap — not policy prose.

Middle West's signature

House taste: curated first, consensus when earned

★ MVP · week 5 — "the House Hundred"

  • v_H = geometric median of ~100 lead-curated exemplar products that are the Middle West look
  • s_H hand-set in a one-hour calibration session against the anchor products
  • Versioned row; the cold-start answer for every anonymous quiz
  • Honest: at week 6 nobody has judgment histories — consensus math would be theater

Phase 2 — earned consensus

  • Per archetype: 10%-trimmed mean of θ_D, weighted by ρ_D · c_D(g)
  • Eligibility: ρ ≥ 0.3 and n ≥ 50 — the newest hire can't drag it
  • No designer exceeds 0.35 of the mass — runaway-capture guardrail, monitored weekly
  • Consensus lands as a draft; activation is human (lead approves)
  • Curation ops as versioned rows: PIN · NUDGE · PROTECT · RESEED — rollback = reactivate

Budget as perception, not a wall

Log-space bell around anchor √(Bmin·Bmax); investment-minded clients center above anchor with wider tolerance. A provenance story + real craftsmanship softens over-anchor prices — and the why says so. Budget never touches style or taste terms.

Weights are data

match_weight_profiles version rows, seeded from the old service's priors. Loop 4 tunes by shipping a new row — never by editing scorer code. Missing terms drop out and weights renormalize; row confidence reflects what was actually known.

Then MMR + two stretch slots

Diversify (≤3/brand, ≤5/color), then 8 exploit + 2 explore sampled Boltzmann-with-novelty from ranks 20–80 — deterministic per session per day, honest in copy: "a step outside your usual — worth a look."

Explainability

No unexplained score path

The whys are computed in the same query that scores. Per-term contributions land in match_events for audit and replay; the top three render through a phrase table — one string source for web, iOS, and marketing, with the copy law enforced where the strings live.

"why": { "terms": { "style_dense": .27, "spectrum": .13, "budget": .10, "patina": .05, … }, "top_reasons": [ { "term": "spectrum", "phrase": "Matches your warm, natural-material leaning" }, { "term": "budget", "phrase": "Comfortably within your range" }, { "term": "patina", "phrase": "The kind of oak that only gets better" } ], "cautions": [ { "term": "context", "phrase": "On the larger side for your room" } ], "blend": { "w": .35, "w_effective": .18, "house_version": 1 } }

How it gets smarter

Five loops, five mechanisms

1
Client implicit signals — interactions → engagement_events (already flowing) → capped behavioral nudges: quiz answers outweigh one restless scroll
2
Designer teaching ★ — confirm/correct drafts + side-by-side judgments → DNA confidence now, θ_D nightly. Every action does double duty — structurally
3
Portfolio ingestion — private bucket → embed → geometric median → v_D0, the cold-start seed that never decays
4
Field outcomes — match_events × saves × purchases → offline replay; weight changes ship as version rows, gated on non-regression
5
Consensus & conflict — the existing 3-touch validation path → confidence upgrades + Phase-2 house consensus with the 0.35 cap

All five write to append-only stores — judgments, corrections, events. Learned state is always a cache that can be refit from truth.

Runtime & operations

Boring on purpose

One outbox, one claim pattern

aesthete_jobs + FOR UPDATE SKIP LOCKED, drained by cron-invoked edge fns in re-entrant batches sized for the 60-second pg_net window. No pgmq, no per-row webhooks, no delivery semantics to babysit.

The worker, sized

2 CPU / 2 GB, int8 ONNX, weights baked into the image (atomic rollback, content-addressed model version). 429 past depth 8 — callers re-enqueue, never spin. ~200–350 ms/image; 5k backfill ≈ 2 h off-peak.

Redis discipline

256 MB is shared — cache only ⌘K query embeddings (≤ 10 MB). Rec results are < 100 ms of SQL; caching them buys invalidation bugs. Rate counters live in Postgres.

Nightly, in phases

02:30 — taste refit → house draft → stats writers → centroids + behavior matview. Deterministic recompute-from-scratch: seconds of work at this scale, perfectly auditable.

Observability substrate

match_events logs every call with contributions — debugging, audits, and Loop-4 ground truth in one table. PostHog funnels + edge-fn events; Logflare structured lines. Engine asks: latency only, no text.

Model migrations

aesthete_model_version on every vector; re-embeds enqueue gradually; mixed states are detectable and scoring compares within-version. A model bump is maintenance, not a migration crisis.

Bias, held responsibly — as mechanisms

Guardrails you can grep for

No runaway house capture

0.35 weight cap + trimmed mean in the consensus SQL; drafts need lead activation; max-share alarmed weekly.

Taste ≠ budget-shaming

Structural: no price features in φ; budget never multiplies style. Audited weekly: craftsmanship served across budget tiers → aesthete_audit.

Against the filter bubble

Exploration floor enforced in the RPC and audited from match_events; novelty-weighted stretch; the client holds the dial.

Human in the loop

Contraindications are hard filters. Drafts never write canon. House activation is a human act. High-stakes stays on designer surfaces.

Explainable by default

Whys computed in the scoring query — an unexplained score is structurally impossible. Your Eye is inspectable; the blend ships in every payload.

The designer's asset

export_designer_taste / retire_designer_taste ship in week 0 — portability and departure are RPCs before they're contract clauses. Raw vectors never reach a client role.

Evaluation

Measured against designers, not vibes

Golden sets first — human ceiling first

G1: 150 products scored by 2–3 designers; Krippendorff's α per dimension before any model is blamed (α < 0.6 → fix the definition). Model bar: MAE ≤ 0.20/dim. G2: "closest 5 of 20" neighborhoods + the category-leak metric that gates the Phase-2 projection.

Does Ana's vector predict Ana?

Chronological backtest: ≥ 65% pairwise accuracy at 100 judgments, ≥ 72% at 300. θ_D must beat θ_H by ≥ 5 points on her own held-out pairs — or her dial's high stop stays locked.

Offline replay, no MLflow

match_events replayed under candidate weights; NDCG vs realized saves. A notebook and a table.

The week-6 demo bar

✓ Zero category errors, zero budget violations across 4 real-client personas

✓ ≥ 6 of 10 endorsed by the designer panel; ≥ 1 "wouldn't have thought of it — but yes"

✓ A plain-language why on every card, passing copy law

✓ p95 quiz → results < 2 s on the all-SQL path

✓ The dial visibly changes the set — house vs a seeded designer's eye
