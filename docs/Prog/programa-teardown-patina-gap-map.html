Module 01 · Schedules & Specification

The spine: a spreadsheet that grew up.

  • Sections by room (Seating, Tables…) with per-section item counts and totals; drag-and-drop, bulk actions, collapse.
  • Four ways in: Web Clipper, Product Library, paste a URL, or manual entry — plus Excel/CSV import with a "smart importer" for messy files.
  • Doc codes (CH02, TB01…) with live duplicate detection; every spec field plus unlimited custom fields.
  • Product record: name, description, brand, SKU, qty, lead-time dropdown, product URL, linked supplier contact, W/L/H/D, color, finish, material, category, custom specs, client-facing and internal notes, image gallery with inset flag.
  • Item statuses drive workflow: Internal Review → Client Review → Approved → Ordered, with per-item assignee.
  • Per-item PDF spec sheets; live-link sharing kills the final_v7.pdf problem.
Observed

Item panel tabs

Summary · Financial · Procurement · Attachments · Approvals

One record carries the spec, the money, the paper trail, and the client's verdict. That's the design lesson worth stealing.

Coming

Schedules 3.0

Announced as the next chapter: one source of truth per project with flexible organizing, filtering, sharing, and presenting.

Module 02 · The Money Layer

Every line item knows its margin.

A second lens over the same schedule. Toggle from Summary to Financial and the document re-renders as a P&L.

Per item

RRP · trade price · trade discount % · markup % · client price · client savings % · net profit — each in any currency.

Per section & total

Section subtotals excl. tax, schedule-level client price and total profit, one-toggle bulk markup.

Downstream

Products flow into quotes, POs, and invoices without re-entry; time entries become billable lines.

Coming

Project budgets, advanced time billing, cashflow and per-project profitability — pitched as living inside the project, not the accounting stack.

The pitch: your books know if the studio is profitable; Programa wants to know if this project is.

05 / 16
Module 03 · Client Dashboard & Approvals

The client sees a curated slice, and answers in-line.

  • Two publish paths: to a branded Client Dashboard (added by email) or to the open web as a live link.
  • Visibility toggles per share: supplier, brand, product URL, pricing, details — each on/off per audience.
  • Per-line verdicts: approve / reject / comment with threaded replies attached to the product itself.
  • Access control: add stakeholders by email, regenerate links, revoke instantly.
  • Shared Files: a per-project folder of documents surfaced on the same dashboard.
  • Approval history logged on the item's Approvals tab; pending approvals roll up to the project overview.
This is the strongest single module in the product — the approval loop closes inside the spec document, and the paper trail rides the item forever. Patina's portal must match this loop before it can beat it.

Module 04 · Procurement

From approved line to supplier email in two clicks.

Quotes

Send Quote Requests

One action emails each supplier automatically with project name and address, product info, and quantities — scoped so each supplier sees only their own items, never the whole schedule.

Orders

Purchase Orders

Numbered POs (PO00001…) built by selecting products from a schedule. Supplier send-to, issue and delivery dates, tax rate, a supplier note, running subtotal/tax/total, PDF preview, draft state, and preview-&-send by email.

Item status chain

Internal Review → Client Review → Approved → Ordered

Procurement state lives on the same record the client approved.

Roadmap tell: the "Brands" program — quoting, procurement, supplier collaboration, purchasing — is Programa building toward the maker side of the market. That is Patina's revenue thesis. They are walking toward it from the designer side.

Module 05 · Capture & Product Library

Their capture is good. Ours is deeper.

Programa
  • Web Clipper with Smart Fill — pulls name, pricing, imagery, URL, description from supplier pages into a schedule, the library, or both.
  • Add from URL — paste a link, get a populated record.
  • Refresh from source — re-sync a product's details from its original URL in one click.
  • Product Library — studio-wide database searchable by brand, supplier, SKU, tag, name; custom products; file import; demo seed data.
  • Image Library + Address Book round out the shared asset layer.
Patina today
  • Chrome extension (T-01) — structured capture, recognized-data states, richer than a clipper.
  • iOS field capture (T-03) — camera-first, offline-first, Action Button / Control Center / Share Sheet / Siri entries. Programa has no field-capture story at all.
  • Capture Inbox (T-05) — captured-vs-verified split, completeness scoring, keyboard triage, duplicate merge. Programa has nothing like a verification pipeline.
Hold this lead. The gap analysis says: don't rebuild their clipper — finish the verified-record pipeline theirs can't match, and add their two cheap tricks (URL paste-in, refresh-from-source).

Module 06 · Pinboards & Presentations

The visual layer clients actually look at.

Pinboards

Mood boards in minutes

Sections by room, revision, or site visit. Auto-snap layout, drag from device, import from Pinterest, pull from the Image and Product Libraries, or clip from the web. Presentation Mode for clients, Detail Mode for notes and links. Shareable and archivable per section.

Presentations

Paged client decks

Multi-page canvas with selectable page sizes, "pins" that pull live products from schedules, duplicate/copy-to, PDF export, and web sharing. Positioned as the stage for the project's content.

  • Canva Share is a first-class project file type alongside Schedule, Presentation, and Pinboard.
  • Project Files hub lists all artifacts with type, share status, and last-updated — one flat surface per project.
09 / 16
Module 07 · Studio Management

Projects, phases, and the whole-studio view.

  • Views: Board, List, Timeline per project; a Studio view runs the same lenses across every project at once.
  • Phases (Concept, Schematic, Design Development, Project Admin — or custom) tag tasks; kanban columns To Do / In Progress / In Review / Done.
  • Tasks carry subtasks, members, target and key dates, labels, comments, up to 50 attachments, and a per-task timer.
  • New Timeline: drag a phase and dependents move with it — rescheduling as scenario-testing, plus a cross-project clash view.
  • Project Overview dashboard: active/overdue tasks, pending approvals, time tracked, total schedule value, invoice count.
  • Meetings (beta): record or upload a transcript; it returns decisions, action items, and open questions.
Read

Assessment

Competent, not exceptional — a design-flavored Asana. Its power is adjacency: tasks link to products and schedules, and approvals feed the same overview. Patina should not chase full PM; it should make project state legible around the Document.

Module 08 · Back Office

Time, invoices, payments, books.

Time Tracking

Global start/pause/resume timer with smart project assignment, manual entries attachable to tasks, grouping by project/person/date, export, and time-to-invoice-line conversion.

Invoicing + Programa Pay

Invoices assembled from schedule products, tracked time, and custom lines. Branded, mobile payment portal for card and bank transfer, chargeback protection, "paid 3× sooner" pitch, business + payments onboarding flow.

Accounting sync

Xero and QuickBooks integrations sync transactions and attachments. Tax settings, invoice settings, and studio branding live in workspace settings.

This is where the $71/seat gets justified — and where a payments margin quietly accrues to Programa. Patina's answer is strategic, not imitative: our revenue is the maker commission, so the back office can stay thin.

Module 09 · Their Assistance Layer

They are walking into our territory.

  • Pulse — a per-user command center: onboarding, "today's focus," and machine-suggested actions with feedback thumbs.
  • Smart Search — cross-entity (products, projects, schedules, tasks, contacts), forgiving of imprecise names, keyboard-first.
  • Meeting Notes — transcript → decisions, actions, open questions, per project.
  • Alternative Product Recommendations — when a client rejects an item with a comment, the system reads product + comment and proposes an alternatives shortlist in Pulse and the Approvals tab.
  • SketchUp extension (beta) — Product Library inside SketchUp, 3D Warehouse match-finding from saved product data, product images as materials, spec-vs-model sense checks.
Alternative Product Recommendations is a generic first pass at the exact problem Patina's Designer-Taught Intelligence exists to solve — theirs reasons from one rejection comment; ours is built to reason from a designer's accumulated taste. The moat is real but the clock is now running.

Build Order

Match the loop, then break it open.

Phase A · Parity spine

The Spec Document

Schedule-equivalent inside the Document model: sections, doc codes, statuses, item records fed by the verified catalog. Plus URL paste-in and refresh-from-source in capture.

Phase B · Close the loop

Client share & verdicts

Publish a curated view with field-visibility controls; per-line approve/reject/comment; approval history on the record. This is the module clients compare directly.

Phase C · Money & makers

Financial lens + orders

Trade/markup/client-price fields and totals as a view over the same document; quote requests and POs that ride the maker network instead of cold email.

Phase D · The moat

Taught intelligence

Rejection-aware alternatives seeded from the expertise layer — reasoning from taste history, not one comment. The feature Programa just previewed, done the way only Patina can.

Deliberately not chased: full PM, time tracking, invoicing, payments. The commission model keeps tooling free and the surface focused.
