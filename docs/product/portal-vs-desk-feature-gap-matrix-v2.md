_Designer Portal · generated **2026-07-01** · audit head git `03537b18` @ migration `00235` · method: **10-shard claim sweep + 10 adversarial verifiers + merge + live Chrome walk; supersedes the 2026-06-14 baseline** (`portal-vs-desk-feature-gap-matrix.md`)._

> **Companion artifacts:** `portal-vs-desk-feature-gap-matrix-v2.html` (presentable deck) · `portal-vs-desk-feature-gap-matrix-v2.rows.json` (canonical row-level data, verbatim from the re-audit) · `the-document-reaudit-walk-2026-07.md` (live-walk report, stations 0–22 + findings F1–F10).

## Executive summary

Across **202 mapped `/portal` capabilities**: **66 FULL · 50 PART · 51 XFRM · 33 ABSENT · 2 RETIRED** in `/desk` today — plus **33 Document-native** capabilities with no `/portal` analog. The 2026-06-14 baseline read **47 FULL · 53 PART · 14 XFRM · 86 ABSENT** (+21 native).

**The shape change is the story.** ABSENT collapsed **86 → 33**, and most of it did **not** land in FULL — it landed in **sanctioned XFRM (14 → 51)**: Tracks 4–6 (the Drafting Room, the generalized ball-in-court coordination, the lead-capture funnel), the People Room, the Decision Composer, the Piece, the proposal watch view, and the Account sheet each *reconceived* an old cluster under an explicit ruling rather than porting it 1:1. FULL grew 47 → 66; PART held roughly steady (53 → 50) as verifiers pushed over-optimistic FULL/XFRM claims back down.

**Priorities** (assigned on PART + ABSENT rows only): **P0 6 · P1 39 · P2 38** (baseline: P0 46 · P1 75 · P2 18).

**The six P0 rows form exactly two clusters:**

1. **Invoice authoring & settlement** — `BIL-02` payment recording · `BIL-03` typed line kinds · `BIL-04` unbilled-time pull-through · `BIL-05` FF&E item invoicing · `BIL-09` invoice detail acts (void / resend / print / payment history). The money-settlement half of the core loop still lives in `/portal/billing`; InvoiceBody dead-ends at "Sent · awaiting payment".
2. **Vendor creation** — `PRC-03`. No maker/vendor create anywhere in the Document (the People Room '+ Add' is client-only); ordering a line requires a vendor row, so a procure loop with a new vendor cannot complete in `/desk`.

**11 verifier overturns**, every one a **downgrade of an over-optimistic claim** (FULL→PART ×7, XFRM→PART ×3, RETIRED→ABSENT ×1) — see [Verifier overturns](#overturns). **45 rows carry a needs-ruling flag** (`needsRuling` in the rows JSON); the recurring themes are unsanctioned sub-function drops, error-path grammar (F2b), and the no-login-household send path (F7).

## Method & accuracy caveats

Produced 2026-07-01 against HEAD `03537b18` (migration `00235`) by: **10 shard claim agents** (one per zone shard, reading real `page.tsx` + hooks + migrations, not route names) → **10 adversarial verifiers** (one per shard, independently re-tracing every doorway and data read; 11 overturns, all downgrades) → **a merge pass** (rulings index + route delta reconciled) → **a live Chrome walk** (22 stations, findings F1–F10).

- **Caveat 1 — agent sweeps can misread code.** Every row carries `file:line` evidence in `portal-vs-desk-feature-gap-matrix-v2.rows.json`, and every claim was adversarially re-verified, but only walked rows are *behavior*-proven.
- **Caveat 2 — walk coverage is partial by design.** The walk covered the 55 walkCandidate/P0 rows across 22 stations; rows outside that set are code-verified only. Not walked: `/compose` (L4-validated previously), the client-portal mirror, mobile <980px, teaching validate/XLSX/team/scan-viewer (absence confirmed by code agents; the ⌘K negative probes proved the fall-through pattern).
- **Caveat 3 — screenshots are in-conversation only** (`save_to_disk` yields no file — standing environment constraint); screenshot debt logged per convention.
- **Caveat 4 — counts are capability-grain**, not usage-weighted; the roadmap tiers add the prioritization the raw counts lack. XFRM ≠ gap: those rows are deliberate, ruling-sanctioned reconceptions.
