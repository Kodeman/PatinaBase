# design-sync notes — @patina/design-system

Repo-specific gotchas for syncing `packages/patina-design-system` to claude.ai/design.
Read this before every re-sync.

## Shape / toolchain
- **Shape: storybook.** Framework `@storybook/react-vite` (Storybook 8.6). Stories glob `src/**/*.stories.@(js|jsx|ts|tsx)` (76 story files, ~100 storied components). `@` → `src` alias in `.storybook/main.ts`.
- **React 19.2.4** (satisfies the 18+ requirement). `react`/`react-dom` are `external` in tsup, so the DS dist does not bundle React — the converter vendors it.
- **DS build:** `pnpm -F "@patina/design-system..." build` (tsup). Emits `dist/index.js|cjs`, `dist/tokens/*`, `.d.ts`. **No CSS in dist** — tsup only bundles JS. The component CSS therefore comes from the storybook scrape (`[CSS_FROM_STORYBOOK]`), not a `cssEntry`.

## ⚠ Tailwind v4 drift — reference storybook needs a custom build
- The DS package.json declares `tailwindcss: ^4.0.0` (resolves to **4.2.1**) but is authored entirely for **Tailwind v3**: v3 `@tailwind base/components/utilities` directives in `src/styles/globals.css`, a v3 JS config (`tailwind.config.ts`), and `tailwindcss` used directly as a postcss plugin. A bare `npx storybook build` therefore **fails** at postcss: *"trying to use `tailwindcss` directly as a PostCSS plugin … moved to `@tailwindcss/postcss`"*. Only the manager builds; `iframe.html` is never emitted.
- **Production truth is Tailwind v3.4.x** — the Next.js portals (`apps/*`) depend on `tailwindcss ^3.4.1` and compile the DS source with their own v3 config. `tailwindcss@3.4.19` is in the pnpm store.
- **hsl vs oklch:** the DS's `tailwind.config.ts` wraps tokens as `hsl(var(--x))`, but the tokens in `globals.css` are **oklch** triplets (e.g. `--background: 0.9582 0.0152 90.2357`). `hsl()` of an oklch triplet is invalid → broken colors. The **designer-portal** config wraps them as `oklch(var(--x))` with byte-identical token values — that is production. So the reference build compiles with an **oklch-corrected** copy of the config.
- **Build the reference storybook with `.design-sync/build-sb-reference.sh`, never a bare `npx storybook build`.** The script temp-patches `postcss.config.mjs` (→ tailwind v3 + oklch config) and `.storybook/preview.ts` (→ imports the font/token contract), builds into `.design-sync/sb-reference`, and an EXIT trap restores the patched files (repo left byte-identical). Re-run it whenever DS source changes (alongside the tsup build).

## Fonts / typography contract
- The DS components expect the **host portal** to provide brand fonts + CSS vars; the DS's own `globals.css` does not define them. Portals load Inter / Playfair Display / DM Mono via `next/font/google` and define `--font-display|body|meta`, `--font-heading|inter|mono`, `--text-primary|body|muted`, `--color-*`.
- `.design-sync/portal-contract.css` reproduces that contract (Google Fonts CDN `@import` + `:root` vars, mirroring `apps/designer-portal/src/app/globals.css`). It is injected into the preview by the build script, so both the oracle and the scraped `_ds_bundle.css` carry the fonts/vars. Fonts load remotely (`[FONT_REMOTE]`) — acceptable; the portals self-host the same families.
- If validate still prints `[FONT_MISSING]` for a family, check portal-contract.css lists it and that the scrape carried the `@import`.

## Preview authoring patterns (from grading)
- **[GENERAL] Full-bleed image cards under `layout: 'centered'` stretch + clip in the preview.** Components whose root is `w-full`/block with no max-width (ProductCard, likely other image cards) render at their intrinsic ~image width in storybook's centered layout, but fill the full-width preview page — the aspect-ratio image then balloons and pushes the card content below the capture (looks blank). Fix: author `.design-sync/previews/<Name>.tsx` that wraps each composed story in a fixed-width `<div style={{width: N, margin: '0 auto'}}>` (single vertical card ≈ 400px, horizontal/list ≈ 640–680px, multi-card grid ≈ 880px). See `previews/ProductCard.tsx` for the copy-the-cache-compose-then-wrap recipe. This is NOT a global config fix — it's per-component for the image-card subset.
- **[GENERAL] Storybook addon-actions auto-injects `on*` callback spies** (argTypesRegex `^on[A-Z]`). A component that conditionally renders an affordance based on a callback prop's truthiness (a remove `×`, a close icon, a dismiss button) shows it in the storybook render but NOT in the generated `compose()` preview (which only mirrors *declared* story args). Symptom: preview missing an interactive affordance storybook shows on an args-based story. Fix: own the preview and pass the `on*` callback explicitly for that story (see `previews/Tag.tsx` — passes `onRemove: () => {}` to Default). Recurs in any batch.
- **[GENERAL] The beige panel behind a component in the storybook cell is a story decorator, not the component's background** — the preview renders white there. Treat it as an ignorable background/framing difference; grade the component's actual render.
- **[GENERAL] Radix Avatar `Fallback delayMs` (default 600ms) → blank initials in the early capture.** `Avatar.tsx` mounts its initials fallback via `AvatarPrimitive.Fallback delayMs={fallbackDelay}` (default 600). The compare screenshot fires before that, so no-`src` avatars render as empty circles in the preview while storybook (captured later) shows the initials. Fix: own the preview, mirror the story JSX, pass `fallbackDelay={0}` to each `<Avatar>` (see `previews/Avatar.tsx`). Residual: an Avatar built *internally* by another component with the default delay (AvatarGroup's `+N` overflow chip) can't be reached from a preview → grade those stories `close`. Note this is a screenshot-timing artifact — the LIVE card in claude.ai/design renders the chip fine after 600ms. Any wave-3 component embedding an initials Avatar may show the same blank-circle in its sheet.
- **Inherent `close` cases that are NOT fixable in a preview `.tsx`:** `position:fixed` stories (render inline in the preview, fixed-to-viewport in storybook — e.g. Banner "Positions"), and mid-animation value stories captured on different frames (e.g. ProgressBar "Animated"). Grade `close` with a note; don't chase them.
- **Remote images (unsplash) are flaky in the capture** — they load inconsistently on BOTH panels (e.g. ProductCard's hero loaded once for storybook Default, placeholder everywhere else). When both sides show the placeholder consistently the card still grades `match` (the image is external content, not component styling); a story where storybook loaded it but the preview didn't is `close` with a note. Do NOT swap in a different image to "fix" it — that diverges from the storybook oracle.

## Preview authoring patterns (from grading) — part 2
- **[GENERAL] The compare's ds capture is hard-capped at 900×700px; storybook captures full element height.** Any component taller than 700px is bottom-clipped in the preview panel while storybook shows it whole — so tall vertical stacks (CostVisualizer Default 852px / With ROI 722px / Complete 1111px) grade `close` (visible content matches; only below-fold content differs). The width-wrapper recipe does NOT help — narrowing a data-card stack doesn't shorten it. Not a shipped defect (the live product card renders full height); accept `close` with a note, or set `cfg.overrides.<Name>.viewport: "900x1200"` (re-grades on the next full build) if you want the full comparison.
- **[GENERAL] `[RENDER_THIN]` on tiny-SVG components (Icon, StrataMark) is a false alarm** — a 14–24px icon/logo mark falls below validate's changed-pixel threshold but renders correctly. Trust the compare render (raw PNG) over the validate flag; no owned preview needed.
- **[GENERAL] Web Worker / canvas components fail in the preview bundle** — the worker URL resolves to `https://ds-preview.invalid/...` so the component hits its error branch (ImagePaletteExtractor's palette quantizer). Fix: own the preview but do NOT import+spawn the real component; mirror its *success* DOM 1:1 and inline the storybook-observed output (see `previews/ImagePaletteExtractor.tsx`). The source image still loads; only the worker fails.
- **`@ds-stories/<repo-relative>` alias needs a FILE path, not a directory** — `.../components/Checkbox` fails ("is a directory"); use `.../components/Checkbox/Checkbox`.

## ⚠ Shipped-component limitations (tell the user / flag on re-sync)
- **DataTable is broken in the bundle.** It's the lone `@tanstack/react-table` (v8.21.3) consumer and throws `Cannot read properties of undefined (reading '0')` when building a row model with actual rows — **only in the esbuild IIFE bundle** (its vitest test passes). Inlining the data doesn't fix it (proven). So all row-rendering stories are `cfg.overrides.DataTable.skip`; only `Empty` ships (cardMode:single, primaryStory:Empty). A design built with DataTable + real rows will hit the same crash — this is a real DS/bundling bug worth fixing upstream (likely a tanstack ESM/CJS interop issue under IIFE bundling).
- **ApprovalTheater**: all 4 modal/portal stories are `sb-error` (render outside `#storybook-root` at capture — blank in storybook) and are `skip`ped. The rich theater ONLY renders when a modal story is unskipped (its portal paints into the card DOM) — but an unskipped sb-error story fails the driver's capture gate, and a *skipped* story can't be a working `primaryStory` (the card floors to ~8KB). So the card ships as the verified `Default` trigger button (`cardMode:single, primaryStory:Default`); the rich "Living Room Design Proposal" theater renders on click in a real app but can't be shown/verified inline in the preview. (Verified visually it CAN render — see earlier render-check — it's a gate/portal limitation, not a component defect.)
- **Carousel**: the `AutoPlay` and `WithImages` stories use `autoPlay` (infinite interval → the capture never settles) + `picsum.photos` remote images that hang the compare for 10+ min. Those + `ProductCarousel` (remote images) are `cfg.overrides.Carousel.skip`; the 5 static stories ship and match. On re-sync, do NOT un-skip them unless the capture harness gains an autoplay/settle bound.

## Re-sync risks (watch-list)
- **Reference build is not the repo's own storybook script.** A future run that forgets `build-sb-reference.sh` and runs `npx storybook build` will fail (v4) or, if the repo later "fixes" to v4, would render differently — always use the script and rebuild the reference when DS source moves.
- **oklch correction is a sed on `tailwind.config.ts`** (`hsl(var(` → `oklch(var(`). If the DS config is ever migrated to oklch (or to Tailwind v4) upstream, the sed becomes a no-op / the script needs revisiting.
- **portal-contract.css values are copied from `apps/designer-portal/src/app/globals.css`** (colors, font stacks). If the portal palette changes, re-copy them, or the oracle drifts from production.
- **Fonts load from the Google Fonts CDN** at build/verify time — a network-sandboxed shell blanks them on both panels (`[ASSETS_BLOCKED]`), which can mask font issues. Verify with egress to fonts.googleapis.com / fonts.gstatic.com.
- **Story cap (6) leaves tail stories ungraded on the busiest components** — Pagination (11 stories), Grid (14), Flex (13), Spacer (13), Breadcrumbs/Command/Tabs (8 each), etc. The primary 6 graded `match`, so they're verified-by-upload in full; the tail was never individually captured. If a later audit wants those variants verified, re-run compare with `--max-stories <n>` for the named components.
- **AvatarGroup `+N` overflow chip** stays blank in its sheet (see the Radix Avatar delay note) — graded `close`, not a shipped-quality defect.
- **`tailwindcss@3` path is discovered from the pnpm store** by glob (`node_modules/.pnpm/tailwindcss@3*`). A version bump changes the dir hash — the glob handles it, but a full removal of the v3 dep (if all portals move off v3) would break the reference build.
